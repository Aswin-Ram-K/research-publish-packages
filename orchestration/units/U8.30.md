# U8.30 — is the "assertion that cannot fail" class LOCAL or SYSTEMIC?

**Status:** partial→done (audit; nothing edited under `src/` or `tests/`)
**Bound:** ≤18 work calls. **Zero LLM calls. No network.**
**Write paths:** `orchestration/units/U8.30.md`, `orchestration/handoffs/U8.30.json`,

## Question
U8.25 found, in the guard enforcing this build's handoff contract, a family of assertions that
cannot fail (`copy == copy`, a pure tautology, and two more of that shape) guarding an exemption
list that measurement showed was 100% stale. Is **that class** LOCAL (one file) or SYSTEMIC?

## Method
Static analysis + targeted reading. No whole-suite run (bound). A throwaway demonstration tree was
built under `state/verify/U8.30/`; the real import was confirmed before any claim was made
(`IMPORTED_FROM read_manifest=src/resextract/docket/manifest.py`,
`IMPORTED_FROM _block=tests/test_docket_reassembly.py`).

## Sweep coverage
56 `.py` files under `tests/` (43 test modules + `tests/conftest.py` + 12 fixture modules);
738 `def test_` functions statically counted. Every test module was parsed with `ast` and scanned
for: constant-true asserts, self-comparisons, `in`-self, `pytest.raises` without an inner assert,
assert-free tests, `isinstance`-only tests, empty-literal loops, empty `parametrize` lists,
bare/`pass` except handlers, and suite-wide regex sweeps for `.copy()` compares,
`json.loads` on both sides, `frozenset`/`set`/`sorted` wrappers, skip/xfail markers, and `comm`.
Not examined: `dockets/` payloads (read-only, not needed), `.venv`, `state/` outside logs, and the
bodies of `tests/fixtures/**` beyond an assert sweep (all 12 fixture modules contain **zero**
asserts).

## Confirmed finding
`tests/test_docket_reassembly.py:360-362` (sha256 `492872341ea3`, mtime 1791465571):

```python
assert _block(read_manifest(dock / "MANIFEST.json")) == _block(
    read_manifest(dock / "MANIFEST.json")
)
```

Class **cannot-fail** (also matches the two-derived-values shape: both sides are the same read of
the same file). `_block` is `json.dumps([row.model_dump() for row in m.material], sort_keys=True)`.
Demonstrated — not merely argued: the written form returned `True` for a known-good manifest **and**
for a schema-valid lie whose payload was perturbed, while the value-vs-measurement form of the same
check returned `True`/`False` respectively. A perturbation the assertion cannot observe.

## Refuted candidates (all measured, not assumed)
- 6 always-skip gates: every one measured **open** in this environment. `_GENUINE_GRAPH` exists;
  `state/logs/U8.15/repairs/U0.22.before.json` exists; git is on PATH and we are in a work tree;
  the UDP route probe yields `192.168.2.187`, so `test_dashboard_auth.py:276` never fires. The
  `--live` skip is intentional and made loud by `pytest_terminal_summary`.
- 6 assert-free tests: they delegate to assertion-bearing helpers (`_assert_guard_a/_assert_guard_b`,
  15 asserts) or assert acceptance by not raising.
- 8 `except …: pass` handlers: 3 are the *correct* `else: raise AssertionError` idiom; 5 are
  environment-probe/cleanup fallbacks.
- 30 of my own first-pass `pytest.raises` flags were the legitimate post-block-assert pattern.

## Weakened class (systemic, but a DIFFERENT class from cannot-fail)
75 `pytest.raises` blocks (of 93) carry neither `match=` nor any assertion on the caught exception;
23 of those sit in tests with no assertion at all. These **can** fail (no raise, or wrong type), so
they are **not** cannot-fail — they are blind to *which* diagnostic fired. Direction of error:
cannot-distinguish, not cannot-fire.

## Fails-spuriously (the other direction)
**0 confirmed.** No `comm` anywhere in `tests/`; `set(cli.IMPLEMENTED) == IMPLEMENTED_SUBCOMMANDS`
compares set-to-set-literal; no `X == X.copy()` form anywhere.

## Verdict
**LOCAL.** One new genuine instance in a second file; no recurrence across 738 tests in 43 modules.
The broad weakness in this suite is the *type-only* class, which is systemic but distinct and
falsifiable.
