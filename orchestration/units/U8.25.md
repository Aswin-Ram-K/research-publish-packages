# U8.25 — fix the flaw U8.22 named: the frozen-baseline guard asserted copy == copy

**Purpose (one):** replace the guard's two-copy baseline design with a single, hash-pinned
source per baseline, and settle the two loose ends U8.22 handed up.

**Hard bound:** target ≤18 tool calls; **actual 38** (37 executed + the mandated
`send_message` to the parent), disclosed: **+11 recovering from writing this handoff badly

## The flaw, quoted

`tests/test_orchestration_handoffs.py:230` (pre-U8.25):

```python
    assert json.loads(BASELINE_GAPS_PATH.read_text()) == BASELINE_GAPS, (
        "U8.15 baseline on disk disagrees with the inline frozen copy")
```

That compares two copies of the same record — the inline dict and the file — and **never
either copy against the measurement**. Two copies of a wrong value agree perfectly, so the
assertion cannot see a transcription error in either one. U8.22 found V6E.json's verified
gap under-declared exactly that way. The identical shape appeared twice more in the same
test: line 233 (`recorded["contract_verifier"] == VERIFIER_CONTRACT`) and line 234
(`recorded["gaps"] == VERIFIER_BASELINE_GAPS`).

## Design chosen: (a) single source + (b) hash-pin, plus a tightening (c)

- **(a)** Both inline baseline copies are deleted. Each JSON file is the sole source.
- **(b)** Both files are now sha256-pinned by a constant in the guard (U8.15's file already
  was, per U8.22's note; **U8.18's was not**). Any byte edit — a repair or a slip — fails
  unless the pin is edited too: two visible acts.
- **(c, tightening only)** `test_no_baseline_entry_over_declares` re-measures the corpus and
  fails when an exemption claims more than the live handoffs need. This is the ONLY
  re-derivation, and it is not vacuous: the exemptions come from a pinned file while the
  measurement comes from disk, so they can disagree — and did (V5.25.json; U8.15's 41 dead
  `V*` entries). A free re-derivation of the *baseline itself* was rejected: it would
  re-absolve every known gap on every run (tautology).
- **Proves:** a silent transcription slip into a baseline is now impossible; a deliberate one
  is visible in two places; a stale/over-declared exemption is caught rather than hiding a
  fixed file.
- **Does not prove:** that the frozen exemptions were right when recorded (U8.15/U8.18's
  measurement is relied on, not re-derived), or that a handoff is truthful — only that it
  parses and carries its contracted keys.

## Also fixed: the stale exemption list and its tautology

`BASELINE_NO_STATUSISH` exempted 13 `V*` files from carrying a status key, guarded by
`assert set(BASELINE_NO_STATUSISH) == set(BASELINE_NO_STATUSISH_FROZEN)` where the frozen
name was `frozenset(BASELINE_NO_STATUSISH)` — a **pure self-comparison that can never fail**.
Measured live: **zero** handoffs lack a status/verdict/result/overall key, so the exemption
protected nothing and would have silently tolerated one of the 13 losing its status. Both
the list and the exemption clause are gone; every handoff must now declare its outcome.

## Loose ends

1. **`V5.25.json` over-declaration → REMOVED** from the U8.18 record (`[next_unit_hint]`
   against a measured `[]`). An over-declaration hides a fixed file; the note recording the
   removal is inside the pinned file itself.
2. **U8.15's dead `V*` entries → RETIRED** (41 of them). `classify()` sends every `V*` name
   to the verifier contract, so those unit-shaped lists could never be read; a future reader
   would have taken them for enforced gaps. Measured stale besides. Only the 4 real unit
   entries remain, so the unit baseline is now 4 entries — still catching **new** gaps,
   because `_regressions()` flags any file absent from the baseline and any measured key
   beyond the frozen ones (proved by `test_unit_shape_baseline_still_catches_new_gaps`).
