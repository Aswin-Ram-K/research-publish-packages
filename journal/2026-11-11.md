### Prior art folded in, and the four rules it added

The pinning research pass (web only, 2026-11-11) came back and **confirmed the design with numbers
rather than argument**, then added four rules the design was missing. Folded into
`docs/COMPACTION-CACHE-DESIGN.md` §3.6 and §5.2, and into `PREREG-COMPACTION.md` instrument
requirement 2.

**Confirmation.** CONPACT ([arXiv:2608.11242](https://arxiv.org/abs/2608.11242)) measures compactors
retaining **17 %** of injected side constraints, with a forbidden delete performed in **30/100 sessions
after compaction vs 0 before**; a separate constraint store appended to the compacted context reaches
**>90 %** without touching the compactor. The Missing Boundary
([arXiv:2609.11024](https://arxiv.org/abs/2609.11024)) measures **0 %** loss of control when control
constraints are preserved vs **87 %** when omitted. `openai/codex#25792` records progress falling
**97 % → 42 %** after automatic compaction. ACE ([arXiv:2510.04618](https://arxiv.org/abs/2510.04618))
names *brevity bias* and *context collapse* and measures +10.6 % for incremental append over iterative
rewriting. Claude Code's post-compaction table shows the production pattern is **re-injection from disk
by runtime rule**, and that anything not re-injected (hook-added context) is summarised away. The
design's `PINS` layer is that separate store; the 17 % is the cost of the alternative.

**The tension named, not hidden.** Manus deliberately re-injects its `todo.md` at the **end** of the
context every step for recency ("avoiding 'lost-in-the-middle' issues"). That is the opposite placement
from this design and it is deliberate: **head buys cache, tail buys recency.** The design chooses the
head because its pins are durability pins, not attention pins; a recency pin is a different object and
is out of scope.

**Engine fact.** SGLang's eviction policy "cannot pin KV in memory — a node protected by the policy is
still evicted if reclaiming everything else is not enough". A pin is therefore a prompt-layout
invariant plus an idempotent re-prefill, never a cache reservation.

**Four rules added.** (1) **Cap the pin block and refuse on overflow** — silent truncation drops
everything past the limit on the next load (Claude Code's own documented behaviour), so `pin()` refuses
and returns the overflow. (2) **Stamp every pin with its turn** (`P7|blocker|T31|…`) — an unstamped pin
cannot be aged out or superseded. (3) **Supersede, never silently overwrite** — Claude Code admits that
for contradictory instructions "Claude may pick one arbitrarily"; a `supersedes P7` line makes the
conflict visible in the prefix. (4) **Sanitise pins written from tool output** — the Pillar "Rules File
Backdoor" hid instructions in `.cursor/rules` behind zero-width joiners and bidi markers, invisible to
human and PR review, readable by the model, surviving forks; CVE-2025-54135 is the execution end of that
chain.

**What the prior art does not provide.** No published `NOTES` schema with typed
`warning|blocker|decision|fact` entries exists. The closest primitives are Claude Code's four `type`
values, Cline's heading lists, and CONPACT's separate constraint store. The design's kind set is a
**synthesis**, and both documents now say so instead of implying a standard.

**Also corrected.** An aggregated review advisory flagged that the fold record had been placed in L3
(`work`), which is per-turn — fold-awareness would have existed only on the fold turn and vanished on
turn 25+, worse than the current marker in L1. Accepted as valid: the record is now a **pin in PINS**
(`P<n>|fold|T24|24 turns dropped at epoch 1`), which persists every turn and is append-only, so it
extends the cached prefix instead of rewriting it. Every claim that followed from the L3 placement was
corrected in the same pass (§2.1, the break-even row, prediction 1, the P8 example, the edit surface,
the arm table, and the prereg's instrument requirement 3 and deviation-note line refs).

**Guards.** `python3 tools/doc_check.py` → `OK docs clean`.

### The replay: `pins` is 1.9–2.7× cheaper than `compact`, and the summary call is the whole difference

Built `experiments/ptr-engine/tools/replay_policy_cost.py` (0 requests). It reconstructs a session's
content stream from the transcript (thinking blocks excluded — not re-sent), converts at 3.122
chars/token, derives `L0` from the first turn's usage, and simulates five policies with a

`SUMMARY_TOKENS = 1200`, plus one extra request reading the whole pre-fold prompt), `mask` (tool results
older than 8 turns → 20-token placeholder), `pins` (drop journal, keep `L0 + PINS(850) + recent`),
`pins-recency` (+ 25-token ACTIVE line).

any folding policy, because FIFO changes the front of the prompt and re-prefills everything behind it.
(2) `pins` is **1.9–2.7× cheaper than `compact`** and the entire difference is the **summary call** —
13 folds × ~92 k = 1.22 M of compact's 2.03 M in the 871-turn session. (3) **Masking alone is an unreliable cost win**: it beats `none` in 5 of 8 sessions but is worse in 3
(127 k vs 70 k; 293 k vs 100 k; 16.51 M vs 15.45 M) because it changes the prefix without reducing the
prompt enough to avoid FIFO, and it is worse than `pins` in all 8.

Caveat recorded in the measurement: the model assumes a perfectly stable prefix, so absolute hit rates
(0.99 for folding policies) are optimistic against the real 0.753. The ranking is robust because the
summary-call count is a direct count, not a cache-model output. The quality half of the claim — that
pins retain constraints a summary loses — is **not** measured here; that is what E7's graded arms exist
to test.

Recorded as `experiments/ptr-engine/measure/REPLAY-POLICY-COST-2026-11-11.json`.

### The pin arms exist: `PINS`, the pin API, and a window-pressure fold — 0 requests

Route (b) is built. The pin arms are `pointer-stable` variants with the layer compiler ported in, so
`spcc`'s **pre-fold** prefix is untouched — proven, not asserted: the pre-change `layers.py` was loaded
from `git show f4de200:experiments/ptr-engine/ptr_engine/layers.py` and driven over the same 24 turns,
and `spcc`'s `prefix_sha256` is identical on **turns 1–23** (`2b670f58…` at T1). At the fold turn (T24)
it differs, and that is the intended change: the fold record moved out of `L1` (7 layer units) into
`PINS` (6), so `L1` becomes 0. The earlier claim that it was identical "on all 24 turns" was overstated
— it was checked at T1 only.

**`ptr_engine/layers.py`.** `CompactionState.pins` is the new layer. It renders between `L0` and `L1`
**only when non-empty** — an empty block would insert a second separator and change the prefix bytes of
every arm that never pins, minting a new prefix generation and making the no-pin control incomparable
with existing rows. The fold record is now a **pin** (`P<n>|fold|T<t>|…`) rather than an `L1` marker, so
it persists on every later turn and extends the cached prefix instead of rewriting it.
`prefix_sha256` covers `L0+PINS+L1`.

**`ptr_engine/layers.py`, the trigger.** `fold_at_tokens` plus `CHARS_PER_TOKEN = 3.122` (measured on the
871-turn session) let a fold be forced by **window pressure**, which is the design's trigger. The
compiler has no tokenizer, so the size is estimated from characters; `_layer_tokens` is a word count and
is explicitly not used. The default is `None`, so every existing arm keeps the turn interval.

**`longrun/arm_cd.py`.** `ARM_PINNED` / `ARM_PINNED_RECENCY`, `PinnedArmState` with `pin` / `retire` /
`pins` implementing the four rules (turn stamp, cap-refuse with the overflow returned, `supersedes P<n>`
instead of an edit, sanitise zero-width and bidi characters from tool-sourced text), the turn-1 `PLAN`
pin, and an `ACTIVE` line gated on `recency` so `pinned` and `pinned-recency` genuinely differ.

**`longrun/run_longrun.py`.** Both arms registered in `ARMS` and `PREDICTIONS`, the tool channel
required, and a `LAYER ACCOUNTING` section in `--dry-run` that prints each arm's layer keys, distinct
prefix count and first prefix change — so the acceptance criterion is observable from the dry run itself
rather than inferred.

**A real gap found by the dry run, and fixed.** The first port folded on `compact_every` only, so
`pinned` on `LR-07` showed `distinct_prefixes=10 first_prefix_change=T25` — nine folds at the 24-turn
interval, not the ~4 a 70 %-of-131072 threshold implies. Adding the window trigger alone did not fix it:
a 24-turn interval folds at ~69 k tokens on a 45 k-token `L0`, well under the 91,750 threshold, so the
interval always won and the window trigger was dead code. The interval is therefore **disabled when the
fixture declares a window** (`compact_every = len(turns) + 1`), and window pressure is the sole trigger,
which is what the design says.

### Two pin-API defects found by driving the real arm — 0 requests

Neither was caught by the port's own tests, because both are in the API surface rather than the render.

**D1 — `supersede` rejected the id `pin()` returns.** `pin(..., supersedes=pid)` did
`int(supersedes)`, so passing back `"P2"` — the exact string `pin()` had just returned — raised
`ValueError: invalid literal for int() with base 10: 'P2'`. An API that hands out `P<n>` must accept
`P<n>`. Both forms now work.

**D2 — the pin cap was measured in words, not tokens.** `_pin_tokens` was
`len("…".split())` while the constant is named `PIN_CAP_TOKENS` and the design calls it a token budget.
A 200-character unbroken pin therefore cost **1** "token", and 200 such writes were admitted against a
512 cap — roughly 200× the intended block. The cap now uses the compiler's own `_estimate_tokens`
(`CHARS_PER_TOKEN`), the same unit the window trigger uses; the same 200 writes are refused after **6**,
with the overflow carried on the exception.

**`longrun/tests/test_pinned_arm.py`** (10 tests) pins both, plus the turn stamp, sanitisation of
zero-width/bidi characters from tool-sourced text, retire-as-tombstone (no removal, no renumbering),
unknown-kind refusal, the PLAN written once and surviving a fold, the ACTIVE line present only on the
recency arm, PINS absent when empty, and the window-pressure threshold. 57 contract tests pass.

**A note on the port's final shape.** The subagent's last write landed after my first edits and settled
on a cleaner design than the one I had started: `compact_every=None` by default for the pin arms, so
there is **no** turn interval at all and window pressure is the only trigger, with a caller-named
interval kept as a floor. That is what the design says, and it is what the code now does.
