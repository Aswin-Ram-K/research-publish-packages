# U5.5 — commit-pinned material extraction + sealed window

**Purpose.** Make `resextract materialize` resolve material at the recorded commit
(not the working tree), mark anything unpinned explicitly, and seal the run's
observation window so a docket can never claim verifiability at a commit while
holding bytes from a different commit or an unpinned tree.

**Write paths (only these).** `src/resextract/docket/materialize.py`,
`src/resextract/docket/manifest.py` (additive optional fields only),
`src/resextract/cli.py`, `tests/test_docket_materialize_pinned.py`,
`tests/test_docket_materialize.py`, `dockets/duval/**`, `state/logs/U5.5*`,
`orchestration/units/U5.5.md`, `orchestration/handoffs/U5.5.json`.

**Hard bound.** ≤35 tool calls, zero LLM calls, no network. Not committed.

**Liveness probe.** `curl -sS -m 5 -o /dev/null -w '%{http_code}' http://192.168.2.168:8012/v1/models`
→ `000` (crash-looping). Zero LLM calls made.

## What changed

* `source_mode` / `--source` = `commit` (**default**) | `working-tree`.
  `commit` resolves each request through `GitObjectSource` at the recorded HEAD and
  records `resolved_from="git_object"` + the **blob sha**; `working-tree` is an
  explicit opt-out that records itself as unpinned.
* **No silent fallback.** Untracked at that commit, or not a git repo ⇒ bytes come
  from the working tree but are recorded `unpinned=true` with
  `reason=untracked_at_commit | not_a_git_repo | commit_not_found |
  source_mode_working_tree`, listed in `unpinned_material`, printed as a warning
  line per file, and noted in `MANIFEST.json`. The untracked `.lane-j-scratch/`
  monograph (83,832 B) and evidence review (159,408 B) therefore stay in the
  docket — visible, not silently trusted.
* **Refusal parity is structural, not re-implemented.** The unmodified
  working-tree `Copier` runs its predicates first and its outcome is kept verbatim;
  pinned bytes are staged into a private mirror tree and put through *the same*
  `Copier`, so pinned bytes cannot bypass containment, symlink, secret path,
  secret content or caps. A file refused on the working-tree path is refused on
  the pinned path for the identical reason. `.worktrees/` refs are refused in both
  modes at the ref→request stage.
* **Sealed window.** `assert_quiescent(target, window_s=…)` opens the run (a moving
  target raises `TargetBusyError` unless `allow_active=True`); HEAD is re-read after
  the copies and assembly. Moved ⇒ `window_sealed=False`, `freshness.state="needs_rework"`,
  the reason appended to `HISTORY.md` and to `manifest.rework_open`; the docket is
  still produced.
* **Manifest schema extended additively, schema string NOT bumped**:
  `material[].blob_sha: str|None = None`, `material[].resolved_from: str =
  "working_tree"`, `material[].unpinned: bool = False`, top-level
  `window_sealed: bool|None = None`. Every pre-U5.5 manifest still validates.

## Known limitation (named, not hidden)

A path that is tracked at the commit but **deleted from the working tree** is
reported `not_a_file_in_target` by the ref→request stage before pinning is
attempted, because `_resolve_one` requires the path to exist on disk. Pinning is
only attempted for paths present on disk. Not exercised by the acceptance lane.
