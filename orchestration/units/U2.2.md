# U2.2 — producer identity, honest metering, finish_run, stale run

**Purpose (one):** remove the build's only outright FAIL by making a candidate's
producer a *field* and a call counter mean what it says.

**Bound:** <=35 tool calls (used 38, disclosed). Four fixes + a new v3 suite.

## What was fixed
1. **FAIL A — producer identity.** Additive migration 3 adds `candidates.producer`
   (CHECK over `model|replay|fixture|unknown`, default `'unknown'`), `candidates.model`,
   `runs.model`, `runs.mode`. Every existing row is backfilled from recorded evidence only;
   a row with absent (or half) evidence lands `unknown`. The per-row basis is recorded in
   `state/logs/U2.2-migration.json`. New reads `candidates_by_producer(...)` and
   `may_back_model_claim(...)` (true only for `producer == "model"`).
2. **FAIL B — metering.** `MineReport` and `report.json` now carry `producer`, `mode`,
   `model`, `model_calls`, `usage_records`. `model_calls` counts real outbound requests
   only; `usage_records` is the old counter's true meaning. A client declares itself
   (`producer`/`mode`/`makes_requests`); the replay client reports `makes_requests=False`,
   so a replay run yields `model_calls=0` and `usage_records=N`.
3. **`finish_run` no longer overwrites `notes`** — it appends, so the graph path recorded
   at start survives (`append_notes=False` restores replace semantics).
4. **Stale run repaired** — run 3 (`status='running'`) becomes `failed`, `finished_at`
   left NULL (unknowable), the reason appended to `notes`.
