MEMORY M-1 -- Retry policy for scheduled jobs

A nightly scheduled job that exits non-zero is retried a maximum of 5 attempts, then marked dead.

Tags in the mirror can be re-pointed when the upstream tag moves, so reproducible builds pin by digest. The common trap is rehearsing rollback after the tag, when the previous version has already left staging. Descriptions that narrate the implementation ("refactored X, renamed Y") without stating the why get reviewed as if the why were obvious, and it rarely is. A delimiter inside a quoted span still splits the part when the quote did not open the part. Quoting the standard tier limit for a backfill log is a common and expensive mistake: 30 days is not the limit for backfill, and a backfill log older than 30 days is still present and readable. Callers that want stripping must strip the parts themselves; doing it inside would make positional alignment depend on content. Rehearse the rollback on a staging copy: deploy the candidate, then roll back, then confirm the previous version still serves. The mirror caches on first request and serves subsequent requests locally. A rebuild streams source rows, chunks them, embeds the chunks, and writes new segments. This is not an exception: partially-keyed batches are normal. If many builds fail at once, check mirror health before bisecting individual pipelines. Null fields are backfilled from the other rows in bucket order, so a field that is null in the winner but present in a loser is filled rather than lost. The fan-out exists because a single upstream write can be observed by several collectors at once; without coalescing, the warehouse accumulates N rows per logical write, and every downstream join silently multiplies its result set.
