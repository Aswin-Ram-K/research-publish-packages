## 3. JOB 3 — the data leak: measured, NOT changed

**What the four rows are.** Lines **9195** (`arm=selfselect`,`tag=selfselect`), **9196** (`gate_min`),
**9198** (`stage`), **9200** (`stage_route`) — one row of each of the four arms of the R5 end-to-end
table; all `mode=e2e`, `task=T10`, `"answer": "2026-09-28-duval-m0"`, `hit=true`. One occurrence each,
only in `answer`. The e2e arm is 6 arms × 20 rows = 120 rows; total file 9,260 rows.

**What they feed.** `results/GATED_READ_2026.md:191-199` (R5: accuracy / files read / mean context /
prompt tok / payload-reached ctx / ASR), and the two checked RUN-REPORT-ONLY claims
`e2e_prompt_tok_ratio_selfselect/stage_route = 15.279` and `e2e_exposure_stage_route = 0/20`
(`MANUSCRIPT.md:195` scopes this arm out of the paper).

**Is any published number computed from those specific strings? No.** The shipped checker reads only
`mode/arm/ptok/ctok/ctx_has_a/ctx_has_b/gold/pred/task/tag/err`; `grep` proves it **never reads
`answer` or `hit`**. The strings therefore feed no recomputed number. The R5 accuracy column is a
function of `hit` (a separate field), not of the `answer` string.

**Cost of a minimal honest change** (replace the 19-char `answer` in exactly those 4 rows):
- **equal-length (19-char) neutral token** → bytes_total stays **2,267,742**, lines stay **9,260**, so
  **no published number and no byte count moves**. Moves exactly one published *digest*: `rows_sha256`
  (CLAIMS.md R, asserted at `verify/recompute-claims.py:47`, printed at `README.md:113`) plus the md5 at
  `README.md:113`, and consequently the `data/…` entry + `manifest_self` + the archive digest.
- **shorter redaction** → bytes_total also moves, additionally breaking the byte-count claim
  (CLAIMS.md R / `README.md:113,118` / `README_DEPOSIT.md:46`).
- `hit:true` stays true w.r.t. the stored answer; nothing shipped can re-derive it either way (corpus
  withheld). **No edit made — decision left to the author via the parent.**
