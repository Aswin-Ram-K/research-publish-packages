## 5. Reports and disagreements with the card

1. **The card's two constraints collide on the archive bytes.** "Keep the superseded value as a dated note"
   *and* "the digest changed again" together mean the shipped prose grows: the archive went 125,847 →
   **126,639 B (+792 B)** from the README dated note and the two superseded-digest comment lines in
   `recompute-claims.py`. The *published byte count* the card names (the rows file's 2,267,742) is
   unchanged, and no published number moved. A size-preserving build was possible only by dropping those
   notes; I kept the notes. Flagged, not hidden.
2. **Superseded rows sha256 still quoted at six sites outside my write paths** — `strategy/GATED_READ_REVERIFY.md`,
   `strategy/GATED_READ_RELEASE_CUT.md`, `orchestration/handoffs/UPKGINSTALL7.json`, `UVEREL7.json`,
   `UPKG7B.json`, and `scratch/uleak7/build.log`. All are author-side or historical records, none ships in
   the deposit archive. **Not updated** (out of declared write paths). The same value survives *inside* the
   shipped tree only as the dated note (1 occurrence each in `README.md` and `recompute-claims.py`).
3. **The archive's own size/digest is quoted in no shippable document.** The only `125847`/`25e1e965` hits
   are ULEAK7's own card/handoff and `scratch/uleak7/build.log`; everything else matching is an unrelated
   tectonic cache index or an unrelated count in `state/`. Nothing to update.
4. `duval` in the *paper* directory is now only in `DISCLOSURE_CHANGES.md` (pre-existing accepted class;
   `DISCLOSURE_CHANGES.md:264-269` records it), plus the capital-D `/home/zer0null/Duval` form at
   `CLAIMS.md:8` / `REFS.md:12` reported by ULEAK7. Both are outside the deposit archive, whose extraction
   measures `duval=0`. Not touched.
5. `DISCLOSURE_CHANGES.md`'s Pass 4 deliberately writes the removed value as `2026-09-28-<target>-m0` so the
   disclosure record does not itself restate the leak; the card's "nowhere in the paper" check then holds.
