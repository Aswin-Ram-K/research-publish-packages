## What changed

| Defect | Fix |
| --- | --- |
| 1. baseline handicapped | `NAIVE_APPEND` and `POINTER` render every node's own `node.text` verbatim, in order; the current volatile block is never attached to an emitted message. Volatile now lives only in `NAIVE_MUTABLE`'s invariant header (the sensitivity bound, unchanged). Docstring rule: *a message, once emitted, is never rewritten by a later turn.* |
| 2. POINTER sent less | `POINTER` emits the salted preamble + every non-invariant body in order, byte-identical to `NAIVE_APPEND` for the same chain. New `equal_information(chain, preamble, salt)` asserts equal message count and equal concatenated content. `POINTER_FORK` is the labelled variant (fork root address in the invariant preamble). |
| 3. overstated test | `test_append_only_prefix_stability` now asserts, for turns 1..4 and for both append-only policies: `new[:len(old)] == old`, concatenated-content prefix, and the exact JSON relation `bytes_new.startswith(bytes_old[:-1] + b",")`; the docstring states precisely what is asserted and why the JSON blob is not literally a byte prefix. |
| 4. unclamped value | `normalise_cache` clamps `cached` to `[0, prompt]` (negative prompt → 0). Each upper clamp increments `meter.clamp_stats()["clamped"]` and reports `max_overrun`, so it is counted and reported, never silent. Caller behaviour unchanged (`uncached` was already floored at 0). |
| 5. naming collision | Context verdict refiled byte-identically to `CX-V1.json` / `CX-V1.md`; batch-1 records restored from `git show HEAD:`. `CX-` convention documented in `experiments/context-cache/README.md`. |
