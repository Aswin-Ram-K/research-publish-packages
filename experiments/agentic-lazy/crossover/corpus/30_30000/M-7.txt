MEMORY M-7 -- Internal registry mirror notes

Pushing from a build host fails authorisation and is deliberate. This is why a reader's memory footprint is roughly twice the segment size regardless of how much data the reader has actually consumed. * The 30-minute cap is the interval makeover target, not an error threshold. A parked reader that wakes to an empty segment re-parks immediately. Do not trigger a rebuild to fix a single wrong document. A change that genuinely cannot be split is usually two changes. Write the changelog entry before the tag, so the tag points at text that already exists. Bisection is a search over a space that only makes sense when the failure is a function of the commit. Writing the changelog afterwards reliably produces a release described by whatever was remembered at the end rather than by what shipped. * Refuses to serialise anything that is not a dict at the top level. The point is to test the exact tree that will be tagged.
