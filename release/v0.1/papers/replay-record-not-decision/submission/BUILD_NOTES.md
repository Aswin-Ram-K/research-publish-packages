## Converter changes (all proven output-neutral for the two existing papers)
1. `dename_rules` --- a new optional per-package key: ordered literal prose replacements applied to
   the raw markdown **before** `sanitise()`.  It is not a blanket stripper: each rule names one exact
   string, and a rule that matches nothing aborts the run as stale.  A package that omits the key is
   untouched (`cfg.get("dename_rules", ())`).  Rationale: `sanitise_rules` holds *named* transforms
   (`unit_ids`, `flatten_links`, `footnote_star`), so there was no way to express a targeted,
   paper-specific de-naming.
2. `author_line` --- the previously hard-coded author slot became per-package, so a package can ship
   no author block.  Both existing entries were given the identical literal they already emitted.
3. `bib_source="none"` --- no bibliography environment is emitted at all.  An empty
   `thebibliography` would itself be the "shipped bibliography nothing cites" defect the citation
   guard exists to prevent.
4. `expect_zero_bib` (+ the ordering of `guard()`): for a zero-bibliography package the positive
   check runs **before** `guard_citations()`.  It asserts the output carries no `\\cite`, no
   `\\bibitem` and no `thebibliography`.  The pre-existing bidirectional check remains active and
   is non-vacuous even with `bib_keys == []` (a stray `\\cite` becomes an unknown key; a stray
   `\\bibitem` breaks the count) --- it simply cannot see an empty bibliography environment.  The
   guard is therefore **not** weakened: it is supplemented and re-ordered.
5. A positive **no-author guard**: if a package declares `author_line=None` and the LaTeX contains
   `\\author`, the run aborts.
