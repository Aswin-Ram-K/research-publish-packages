# U8.6 — a broken input must not be reported as success

**Purpose.** Fix two V8B findings in `src/resextract/run.py`: (1) a reuse candidate
that cannot be used (0-byte/garbage/`{}`/zero-node) was accepted and the graph stage
reported `status="ok", nodes=0`, so every downstream stage ran on an empty graph;
(2) the build branch's `planned_out` named `<run_dir>/kg/graph.json` while the
artifact really lands at `<run_dir>/kg/graphify-out/graph.json`.

**Write paths.** `src/resextract/run.py`, `tests/test_run.py`, `state/**`,
`orchestration/units/U8.6.md`, `orchestration/handoffs/U8.6.json`. No commits.

**Fix.** `_graph_unusable_reason(path)` is the single validity check (regular file,
one JSON object, non-empty `nodes` array, `links` present as an array; `communities`
deliberately optional because the genuine artifact has none). It is called only from
`_reuse_candidate`, which both the plan and the run call. Unusable candidates are
reported into `ctx.graph_rejected`/`ctx.notes`, never deleted; the run builds beside
them. `planned_out = str(Graphify.graph_json(out_dir))` — the same locator the build
uses. Adjacent fix: counts reported `edges` via `getattr(stats,"links",0)` (always 0);
now `stats.edges` (genuine graph: 7102).

**Evidence.** Function-level repro/verification of all 8 cases (`state/U8.6_probe.py`,
`state/logs/U8.6_probe_post.txt`), `tests/test_run.py` 25 → 35 collected, 35 passed,
0 assertions deleted. Red→green for both guards, sha256 bit-identical restore with a
full `__pycache__` purge. Live outcome differs from the card: the store was migrated
to v4 by a sibling mid-unit, so `run --target duval --dry-run` exited 0 and planned
`mode=reuse, nodes=2685` on the genuine graph. See the handoff for the honest detail.
