# U5.6 — tree-first commit resolution in `_resolve_one`

**Purpose.** Fix the defect verifier V5 judged: `_resolve_one` required on-disk
existence *before* pinning, so a file tracked at the recorded commit but deleted
from the working tree reported `not_a_file_in_target` and its blob (still in the
object store) was never read. Resolve **tree-first** in commit mode; keep
`not_a_file_in_target` only when the path is absent from **both** the commit and
the working tree. Correct four overstated docstrings.

**Write paths.** `src/resextract/docket/materialize.py`,
`tests/test_docket_materialize_pinned.py`, `state/logs/U5.6*`,
`orchestration/units/U5.6.md`, `orchestration/handoffs/U5.6.json`.

**Bound.** ≤30 tool calls, zero LLM calls, no network, no commit. Only
`tests/test_docket_materialize_pinned.py` + `tests/test_docket_materialize.py`
are run (siblings mid-write).

**Change.** `_resolve_one` takes an optional `pinned_source`; when the path is not
on disk it probes the commit and emits the request on success. `_resolve_sources`
resolves such requests tree-first instead of skipping them, and `_merge_plan`
takes the mirror's verdict for a dest the working tree could not serve.
`materialize_lane` opens the pinned source before refs become requests.
The secret predicates still run over the pinned bytes (mirror Copier), so
committed-only secret content is refused — the intended asymmetry.
