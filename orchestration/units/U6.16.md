# U6.16 — Store resolution is one boundary, and it is observable

**Status:** done · **Bound:** ≤22 tool calls (used 20) · **LLM calls:** 0 · **Servers:** 1 (started+probed+killed in one Bash call)

## Purpose
Make the store-resolution paths consistent so a verifier/test can actually isolate the store, and so no
future unit can believe it isolated state when it did not. Enforce at the boundary, not at instances.

## Finding (verified, with nuance)
`RESEXTRACT_STATE_DB` was honoured by some paths and ignored by others:
- **honoured:** `store.default_db_path()` (`store.py:123`, reference behaviour) and `default_layer()` (`api.py:1338`).
- **ignored:** `DataLayer.__init__` (`api.py:350` → `Path("state/state.sqlite")`) and therefore
  `create_app` (`app.py:110`), which builds its own `DataLayer`.

Demonstrated with `RESEXTRACT_STATE_DB` = a copy (`state/logs/U6.16-probe-before.txt`):
`default_layer()` → the copy; `DataLayer()` and `create_app().state.dashboard["store_path"]` → the **real**
`state/state.sqlite`. Precedence was incoherent and documented nowhere.

## Decision
`explicit --store/create_app(store_path=...) > RESEXTRACT_STATE_DB > cwd state/state.sqlite` — chosen because it
is what `store.py:123` and `default_layer()` already did; only `DataLayer` was wrong. Implemented as the single
boundary `api.resolve_store(explicit) -> (Path, source)`, called by `DataLayer.__init__` and `default_layer()`;
`resolve_journal_dir()` applies the same rule to `RESEXTRACT_JOURNAL_DIR`. `DEFAULT_DB_PATH` is now imported
from `store.py`, so the literal default has one definition.

**Observable:** `DataLayer.store_path/.store_source` + `DataLayer.resolution()`; `create_app` publishes
`store_path`, `store_source`, `store_resolution` into `app.state.dashboard`.
