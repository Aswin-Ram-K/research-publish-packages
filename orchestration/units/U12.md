## How the classifier decides unit vs verifier shape

`tests/test_orchestration_handoffs.py:191` `classify(name, doc)`:

```python
if name.startswith("V") or "verdict" in doc or "overall" in doc:
    return "verifier"
return "unit"
```

So U10.json was read as a **verifier verdict** because it carries `"verdict":
"boundary_specific"` — not because of its filename (`U10` does not start with `V`). The two
shapes are judged against different contracts:

- unit shape → `CONTRACT` (inline, 7 keys, `:114`): `unit, status, artifacts, evidence,
  blocker, next_unit_hint, write_paths`
- verifier shape → `frozen_baselines()[2]` read from the pinned record
  `state/logs/U8.18/verifier_shape_baseline.json`, `contract_verifier` = `unit, overall,
  checks, blocker, next_unit_hint, write_paths` (6 keys)

Hence exactly two keys were missing: `overall`, `checks`.

## How the frozen baselines work

- Two files, each the **sole** source of its record, each pinned by a sha256 constant in the
  test (`BASELINE_GAPS_SHA256` for `state/logs/U8.15/baseline_gaps.json`, and the
  verifier pin for `state/logs/U8.18/verifier_shape_baseline.json`); any byte drift fails
  `test_frozen_baselines_are_untouched_and_recorded` (`:474`). Editing a baseline requires a
  visible second edit to the pin.
- `test_no_new_contract_key_gaps` (`:349`) filters live gaps by shape and calls
  `_regressions()` (`:318`): a filename absent from the baseline is a **NEW** gap; a filename
  present but lacking a key the baseline never exempted is a **WORSENED** gap. Both fail.
- `test_no_baseline_entry_over_declares` (`:440`) checks the tightening direction: an
  exemption claiming more than the live corpus needs fails. The baselines are frozen
  *records*, deliberately never re-derived, so repairing a file never re-absolves it.
- Consequence: the fix is to complete the file, never to add it to a baseline.

## The edit

Added `overall: "pass"` and a 9-entry `checks` array by **pure insertion after line 18**
(`"verdict": "boundary_specific",`). No reordering, no reformatting, no changed values.
`overall` is `pass` because U10 recorded `status: done`, `verdict: boundary_specific`, 159
live requests with 0 wire failures — the measurement succeeded; it is the *boundary* that is
specific, not the outcome. Every `checks` string maps 1:1 onto an existing `evidence` field
of U10.json (pooled contrast, per-length table, delay test, insert test, recovery/tax law,
cold isolation, U4b caveat, budget). No new measurement or number was introduced.
