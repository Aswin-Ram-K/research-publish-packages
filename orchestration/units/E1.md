# E1 — fork-break-cost (mechanism experiment)

**Purpose (one).** Settle GAPS **G1**: do `FORK` and `SUMMARISE_IN_PLACE` have a
*different break cost* at the compaction event, under the **post-U13 library** where the two
policies render genuinely distinct prompts? U4 produced zero informative pairs because both
arms were the same renderer (`POINTER_FORK` never imported; `render` emits `node.text`, not
`node.kind`). This unit re-runs U4's matched-pair design with a hard distinctness proof.

- `cells/U4/u4_cell.py`, `cells/U4/u4_sessions.json`, `cells/U4/u4_runlog.json`, `cells/U4/u4_events.jsonl`

## Design (pre-registered, deviation declared)
| item | value |
|---|---|
| sessions | `u4-s1..u4-s3` (same corpus as U4: 44 turns, 2 800 chars each) |
| turns per session | **38** (was 44: hard 200-request cap) |
| arms | `F` = `CompactionPolicy.FORK` + `RenderPolicy.POINTER_FORK`; `R` = `SUMMARISE_IN_PLACE` + `RenderPolicy.POINTER` |
| budget / keep_last / reps / max_tokens | 8 000 / 2 / 1 / 4 (as U4) |
| summariser | `runner._truncating_summarizer` (identical for both arms) |
| salt | per **session** (`E1:v1:20261020:<session>`), not per arm: makes the pre-fork turns byte-identical across arms so one request serves both until the first event |
| request plan | turns 1–11 shared (11) + turns 12–38 both arms (27×2=54) = **65/session, 195 total** |
| expected events | turns 12,17,22,27,32,37 (6/session ⇒ **18 pairs**; U4's 7th event at turn 42 is outside the cap) |

Deviation vs the card: the card's "3 × 44 turns / 21 pairs" needs 264 live requests
(3×44×2) or 258 with neighbour trimming — both exceed the hard 200 cap. Turn 38 is the
largest symmetric depth that fits (195). The 7th event (turn 42) and its pair are the named
remainder.

## Method
1. Offline plan + preflight (no request): build both chains turn by turn, record planned
   prompts, event turns, and the first byte offset at which the two arms' canonical JSON
   prompts differ per turn. Assert: identical before the first event, unequal at/after.
2. **Distinctness proof, before any live call**: green (marker present) → prompts differ,
   with byte offset + token counts; red (marker stripped / unlabelled renderer) → prompts
   become byte-identical and `e1_analyze.check_distinctness` must raise. Both directions
   written to `cells/E1/e1_distinctness_{green,red}.json`.
3. Live: one request in flight, strictly serial; `fcntl.flock(LOCK_EX)` on
   `experiments/context-cache/.occamy.lock` before the first request, released after the
   last; 1800 s acquisition deadline → `partial`, blocker "lock timeout".
4. Rows: session, turn, arm, prompt_tokens, cached_tokens, uncached, `prompt_tokens % 64`,
   event flag, node ids in window, fork-marker presence, prompt sha256, cross-arm first-diff offset.
5. Analysis: break cost per arm per event = uncached(event) − median(uncached(prev),
   uncached(next)); paired deltas over event index (n = 18), median, range, bootstrap CI;
   no winner claim beyond what the pairs support.

## Bound (hard)
≤ 200 live requests (plan 195), ≤ 45 min, ≤ 30 work tool calls. Abort on 3 consecutive
failures → `partial` with the rows in hand. No single request retried beyond the client's
own 1 retry.

## Result (measured)

Status **partial** (bounds), G1 answered.

- **Run**: 195 live requests / 228 rows / 18 pairs; serial; `lock_wait_s` 0.0; `elapsed_s` 175.709;
  `rows_sha256` `263db62e631737495f99284fbe60fd5121b3d6a7a2cbd7aa2984572dd71984bd`.
- **Distinctness (green)**: arms byte-identical turns 1–11, distinct at/after every event; first differing
  byte offset **222** at all 18 events (inside message 0's header; preamble label at 210, `[fork]` marker at
  302 in the concatenated content; differing message indices `[0,1]`); server `prompt_tokens` delta at events
  median **411** (189–621), offline est-token delta 43–86.
- **Distinctness (red)**: marker-less pre-U13 replay → arms byte-identical at all 114 turns,
  `check_distinctness` raises ("arms render byte-identical prompts at/after the event -- the U4 defect"),
  0 informative pairs. Guard passes green, fails red.
- **Break cost**: median **fork 5132.75** vs **summarise 442.25** uncached tokens; paired delta median
  **+4774.25**, range −2035…+5611.5, 95 % bootstrap CI **[193.5, 4868.25]**, 15/18 positive (p = 0.0075).
  The 3 negatives are all event 2, where both arms recorded `cached_tokens=0`; excluding that stratum,
  n = 15, median **+4839.5**, CI [4677.5, 4901.5], 15/15 positive (p = 6.1e-05).
- **Mechanism**: at events 3–6 the fork arm's cached is **64** against 6464–6528 on its neighbours (full
  re-prefill: the root label inside the header changes at every fold, and the `[fork]` marker sits at the
  first body byte), while the summarise arm's cached at the event is **4352/4416**, the same as its
  neighbours.
- **Remainder**: the card's 3 × 44 turns / 7 events / 21 pairs needs 264 requests (258 trimmed) > the hard
  200 cap. Ran 38 turns / 6 events / 18 pairs (195). Event 7 (turn 42) is unmeasured and cannot be topped
  up (the pre-event cache state would be cold); it needs a 44-turn rerun at a raised cap.
- **Caveat**: the summarise arm's ~4.3k-token reuse depends on the deterministic prefix-truncating
  summariser (successive summaries are nested prefixes). No steady-state winner is claimed here.
