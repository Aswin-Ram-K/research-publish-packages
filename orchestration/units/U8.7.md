# U8.7 — graph provenance: report staleness, never silently reuse a wrong graph

**Purpose.** Close the residual V8B named via U8.6: *a graph that is valid but wrong
(stale / other repo / truncated-but-valid JSON) is silently reused.*

**Bound.** ≤28 tool calls, zero LLM calls, no network, ≤2 live `run` invocations, no
graph build, only `tests/test_run.py`.

## What was found
The authoritative artifact **does** record provenance: `built_at_commit =
6deaed07af0d…` (a real Duval commit, stamped by graphify's `extract` from the
*target's* HEAD) plus `graph.graphify_version = "0.9.80"`. `run.py` never read it:
`_reuse_candidate`/`_stage_graph` reported only mode/nodes/edges/sha256, so a graph
built for a different revision was indistinguishable from a fresh one. The live
graph was already stale (built at `6deaed07`, target HEAD `6c60da5a`) and reused
with nothing said. → recorded provenance exists; the *report* was silent.

## Fix (all in `src/resextract/run.py`; `kg/graphify.py` untouched)
* `_graph_provenance(path, target_head)` → `fresh` | `stale` | `unverified`
  (`unverified` when nothing is recorded or HEAD is unreadable: missing provenance
  is **not** evidence of freshness). Reads `built_at_commit`,
  `graph.graphify_version`; `built_at` stays `null` — graphify 0.9.80 records no
  timestamp and none is invented.
* `_provenance_stamp()` builds the one graph-line clause both paths print.
* Both branches of `_stage_graph` publish `counts["provenance"]` with
  `{built_at_head, built_at, tool_version, sha256, nodes, edges,
  observed_target_head, state, detail}` and a `ctx.notes` line when not fresh.
* Provenance is evaluated **inside `_reuse_candidate`** (same place as the single
  validity check) so plan and run cannot disagree; the spy test still pins 2 calls.
* **Policy: report-only** — a stale graph is reused with `STALE` in the graph line.
  Proportionate because the target's HEAD is moved continuously by a foreign actor
  (`55710509 → cf2f516b → 6c60da5a` observed during this build): "stale ⇒ rebuild"
  would rebuild on nearly every run. Opt-in refusal is `require_fresh_graph=False`;
  a stale candidate is then reported (`rejected_candidates`, label `stale`) and
  **kept on disk**, and a fresh graph is built. Absence of the flag is the safe
  default: never a silent rebuild, never silent trust.
* Where provenance is kept: in the **run report** (`StageResult.counts["provenance"]`
  + `ctx.notes`) — not a sidecar. The durable provenance already lives inside
  `graph.json` (written by graphify itself); a sidecar would be a second,
  drift-prone copy, and writing one next to a *reused* artifact would violate
  "the dry run writes nothing" and the run-scoped-writes discipline.

## Evidence
`tests/test_run.py` 35 → 40 passed, 0 assertions deleted. New guards: (g) stale ⇒
both plan and run say `STALE` and agree; (h) no provenance ⇒ `UNVERIFIED`, never
fresh. Red→green: revert ⇒ `KeyError: 'provenance'` / `AssertionError: unrecorded
provenance was reported 'fresh'`; restore `cmp`-clean, sha256 bit-identical, FULL
`__pycache__` purge between every cycle. Live: dry run exit 0, wrote nothing
(`state/run`, `state/kg` byte-identical), graph line carries
`built at 6deaed07af0d, target head 6c60da5aa924 — STALE`, 2685/7102,
sha `4790bbb1111b`; real run exit 1, `window_sealed=True`, mine/claims/assess
blocked, materialize skipped. Store untouched (v4, `40e8aa0c…`, byte-identical).
Target untouched (HEAD `6c60da5aa924`, porcelain = foreign actor's two untracked
entries, unchanged).

## Residual after the fix
A graph whose recorded commit matches the target HEAD but whose *bytes* were
tampered with still passes (the sha256 is reported, not pinned); a graph from a
matching revision that is nonetheless the best available is not questioned; and a
graph recording a commit from the *building* repo rather than the target is
reported stale/unverified rather than silently trusted. Provenance makes staleness
visible; it does not make the graph correct.
