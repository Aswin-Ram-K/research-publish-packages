# U2.3 — schema v4: producer on `evidence`/`verdicts` (+ `verdicts.model`)

**Status:** done. **Bound:** 32 tool calls (used 40 — overshoot disclosed in the handoff).

## Why
Verifier V4A: *"Store gap => RISK, not acceptable interim. No producer on `evidence`/`verdicts`,
but `candidates` does have one from migration 3 for this exact FAIL-A hazard. `verdicts` is the
higher-stakes table ... Fix: schema v4, producer on both, reusing candidates' vocabulary (`'unknown'`,
not `'none'`)."* A verdict decides whether a research claim is novel; with no producer field a
model-produced verdict was indistinguishable from a replay-produced one.

## What
- `SCHEMA_VERSION = 4`; `_MIGRATION_4` registered in `MIGRATIONS` (4 = additive ALTERs + fail-closed backfill).
- `evidence.producer`, `verdicts.producer`: `TEXT NOT NULL DEFAULT 'unknown'`
  `CHECK (producer IN ('model','replay','fixture','unknown'))` — character-for-character `candidates`'.
- `verdicts.model` `TEXT` nullable, mirroring `candidates.model`.
- Backfill: every pre-v4 row → `'unknown'`; a row must NEVER become `'model'` by default. There is no
  producer evidence in an old row (per-run `report.json`/`verdicts.jsonl` are not the system of record);
  recorded per row in `MIGRATION_NOTES_V4`, following migration 3's half-evidence ⇒ `unknown` precedent.
- Accessors: `evidence_by_producer`, `verdicts_by_producer` (mirror `candidates_by_producer`),
  `may_back_model_claim_verdict` / `verdict_may_back_model_claim`, `model_produced_verdicts`, all
  reusing one shared `_producer_is_model` predicate so candidates/evidence/verdicts cannot diverge.
- `insert_evidence`/`insert_verdict` gained optional `producer`/`model` kwargs (validated against
  `PRODUCER_VOCAB`, default `'unknown'`).
