# U5 — quality arm: does pointer/compaction rendering preserve accuracy?

Status: DONE (batch complete, 760/760 requests, analysis written)

## Purpose
Measure whether the cost-saving context rendering changes answers, against the
incumbent append-only baseline, on real multiple-choice cases with a key
(`experiments/second-labeller-190/cases.json`, 190 cases, read-only).

The unit opened against the original card (POINTER vs NAIVE_APPEND) and was
re-scoped by the orchestrator mid-flight after an independent verifier found
two defects in the then-current `render.py`:

1. `NAIVE_APPEND` re-attached the live volatile block to the newest message, so
   message N-1 changed bytes every turn (artificially bad baseline);
2. `POINTER` emitted only a preamble + a table of node **hashes** + the newest
   delta — earlier turn bodies were not in context, so the comparison measured
   information loss, not rendering.

Revised design actually executed here:

* volatile values are baked into node text at creation and every render call
  passes `volatile={}` — no message is ever rewritten;
* the arms are **compaction policies** (`summarise_in_place` vs `fork`) plus an
  uncompacted `baseline`, all rendered append-only over the same content;
* equal information is asserted programmatically, and the retained-content
  probe (a per-case gold line planted mid-history) is reported.

A sibling unit rewrote `render.py` during this unit (mtime 18:07:16): in the
current version `POINTER` and `NAIVE_APPEND` are byte-identical for the same
chain, and fork bodies are rendered. That makes the original
renderer-vs-renderer question answerable by **assertion** (760/760 cells,
0 bytes differing) instead of by spending requests; the live requests go to
compaction, which is where quality can actually move.

## Design
Depth:
- **shallow** — case alone (no history, `~150` prompt tokens).
- **deep** — case preceded by 12 turns (~8.4k estimated / ~10.8k measured
  tokens) of agent-style session text taken from the pinned U4 corpus; the
  question sits at the end of a large context.

Conditions (deep, all append-only, `render(NAIVE_APPEND, …, volatile={})`):
- `baseline` — no compaction, full history;
- `summarise` — `compact(SUMMARISE_IN_PLACE, keep_last=3)`;
- `fork` — `compact(FORK, keep_last=3)`.

`keep_last=3` is not cosmetic: it makes the final question land on a `user`
turn under the renderer's role alternation (asserted in `u5_cells.build_cell`).
Compaction uses a deterministic, injected extractive summariser (first line of
each folded turn, 180 chars) — no model call, so the treatment is reproducible
and the request budget is spent only on measurement.

One request per cell, `temperature=0`, `thinking=False`, `max_tokens=64`,
`stream=True`, one in flight. The model is asked for the option letter only;
the first option letter in the raw text is parsed (with a strict-parse
sensitivity column), and every raw response is stored in `u5_raw.jsonl` so a
verifier re-parses without re-running.

## Kill condition
Accuracy difference **> 5 points** at either depth ⇒ quality not preserved
(negative result, reported unsweetened). Agreement **< 90%** ⇒ flagged
prominently. Both are computed in `u5_analyze.py::kill_check`.

## Findings (measured, 760/760 HTTP 200, 0 retries, 640.3 s)

| condition | shallow | deep |
| --- | --- | --- |
| baseline (no compaction) | 66.3 % (126/190) | **72.1 %** (137/190) |
| `summarise_in_place` | 66.3 % (shared reading) | **70.5 %** (134/190) |
| `fork` | 66.3 % (shared reading) | **69.5 %** (132/190) |

- **Kill condition on accuracy: NOT triggered.** Largest delta is 2.63 pts
  (baseline vs fork), threshold 5. Paired exact McNemar: baseline vs summarise
  p=0.648 (11 vs 8 discordant), baseline vs fork p=0.383 (13 vs 8), summarise
  vs fork p=0.774 (7 vs 5). No significant accuracy difference.
- **Agreement below 90 % — flagged.** summarise vs fork 174/190 = **91.6 %**;
  baseline vs summarise **87.9 %** (167/190); baseline vs fork **86.8 %**
  (165/190). Aggregate accuracy hides ~10 % per-case flips.
- **Content retention is the real failure.** The per-case gold line planted
  mid-history survives in **190/190** baseline cells and **0/190** compacted
  cells; the question and all options survive 190/190 everywhere. Compaction is
  silently lossy for arbitrary early-turn content, and the aggregate MCQ score
  does not reveal it.
- **Equal information holds where it can be checked.** shallow summarise==fork
  190/190 byte-identical; `POINTER`==`NAIVE_APPEND` 760/760 cells, 0 bytes
  differing; deep summarise==fork 190/190 byte-identical. Any deep accuracy
  difference is therefore a compaction/summariser effect, never a rendering
  effect.
- **Depth effect is positive, not negative.** The same 190 cases score 66.3 %
  shallow vs 72.1 % deep-baseline (13 vs 24 discordant, p=0.099). The pinned
  history is topically related to the corpus (state classes, namespaces,
  grants), so part of this is priming; it is reported as an observation, not a
  claim that long context helps.
- Prompt sizes: shallow median 146 tokens; deep baseline median 10,710; deep
  compacted median 3,146.
- Reproducibility: `u5_analyze.py` re-derives all 760 prompt sha256s from the
  deterministic builder — 760/760 match. The batch ran against
  `render.py` sha256 `4184c9321b9a9406` (rewritten by a sibling unit at
  18:07:16); a later rewrite breaks prompt reproduction.
- Only side effect outside the declared paths: the shared
  `experiments/context-cache/.occamy.lock` now carries a one-line acquisition
  record (the card requires acquiring that file with `flock`).
