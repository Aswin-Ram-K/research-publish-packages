### The 6/48 gap is answer-slot binding

Run: `measure/rows-e3-retain-2026-11-10.jsonl`, arms `spcc` (48/48) and `masking-no-fetch` (42/48), 200 rows, endpoint `http://192.168.2.168:8012/v1` (engine `sglang`), `longrun/tasks-v7/TX-04.v1.json` (gen-7, sha256 `0c836872…`), model `occamy-1.0`, temperature 0, seed 42, window 200 / compact-every 200. Both arms' prompts were rebuilt through the runner's own `Planner` (`experiments/ptr-engine/longrun/run_longrun.py:1562`) with `send_chat` replaced by a recorder, replaying each row's `content` through `Planner.record` and applying `checkpoint_prompt` on the 48 checkpoint turns exactly as the run loop does (`run_longrun.py:3555-3567`). **`prompt_sha256` matched 200/200 rows** — the reconstruction is the prompt the model actually saw.

The structural difference is one line per turn. The masking arm is a flat transcript replay: `WORKING SET`, then 29 turn blocks each shaped `QUESTION (Tt) / TOOL OUTPUTS: / TOOL_OUTPUT (doc@rev): body / ANSWER (Tt): value`, then the current turn block, then the checkpoint contract (T30: 158 lines, 1,611 prompt tokens). The spcc arm is the layered compiler L0/L1/L2/L3/L4 (T30: 69 lines, 1,465 prompt tokens, `layer_tokens` L0=80 L1=20 L2=215 L3=21 L4=2). **The one difference that matters: the masking arm replays an `ANSWER (Tt):` line after every turn's tool-output block; the spcc journal replays no answers at all.** The pinned index, the current turn's delivery appended after the question, and the checkpoint contract are shared.

Mechanism: the transcript teaches a positional rule — the answer slot takes its value from the block immediately above it — because that is the shape of all 29 prior turn blocks. On a checkpoint turn the fixture delivers a body for a *different* document, and that body is the block immediately above the answer slot. Five checkpoint turns deliver a body; in all five the delivered document differs from the asked one; the masking arm answers with the delivered body's value on **4 of 5**, spcc on **0 of 5**.

Answered `4073`, while the expected `4083` sits at line 62 inside `TOOL_OUTPUT (doc-fact-08@1)` delivered at T11 — 90 lines and 428 tokens above the question, and the only occurrence of that value in the prompt.

Two rival explanations are refuted. **Proximity:** at T30 both arms have the answered value closer to the question than the expected one (masking 32 tokens before / 27 after; spcc 21 before / 17 after) and spcc answers correctly. **Document anchoring:** the masking arm does print `TOOL_OUTPUT (doc-fact-07@1): # doc-fact-07` and the model ignores it.

The masking arm's one correct delivery-turn answer (T12) is the turn where the expected value had already been echoed as a prior answer: masking T12 line 55 reads `ANSWER (T10): ANSWER: NUM 4061` — T10's wrong answer is T12's correct answer, so the value appears twice. The two within-document failures have no delivery: T34 answered `4022` = `ANSWER (T22): ANSWER: NUM 4022`, the replayed answer for the same document but a different symbol; T73 answered `4124`, the line immediately below `VAL_C = 4123` in the same body.

**Verdict: intrinsic to a transcript replay that replays answers — not fixable without changing what the arm measures.** The answer replay is load-bearing: the masking branch masks prior answers on masked turns precisely so an earlier checkpoint's value cannot be copied without recovering the fact. Delete the `ANSWER` lines and the arm is no longer a transcript replay — it is the spcc journal, i.e. the other arm.

**Consequence: the 6/48 gap is a format artefact and must be excluded from any retention comparison.** At this cell neither arm loses information (`masked_rows` 0, `compactions` 0, `evicted` 0 on all 200 rows; `expected_present` true on 96/96 with `expected_present_source = prompt-digit-boundary`). The cell is a format control, not a retention measurement. Pooling this 12.5 pp with the distance cliff would attribute a prompt-format artefact to memory.
