# MATRIX-COVERAGE — the denominator every accuracy in this project must be quoted against

**Read this before quoting any accuracy from the LR-01 checkpoint grid.** The grid is not
complete: 36 of its 92 declared cells carry no answer at all, and 13 more are answerable but
undecidable by the instrument. A rate computed as `pass / 92` silently counts those 49 cells as
failures; a rate computed as `pass / decidable` ignores them and looks twice as good. Both are
wrong to quote bare. Every line below prints `passed / decidable` (`decidable = pass + fail`)
with the missing and undecidable counts in the same parentheses, and is marked
**– PARTIAL GRID** whenever anything is missing or undecidable.

Unit `MATRIX-HONESTY`. Zero model requests. Nothing on this page was generated by a model: the
judge is `experiments/ptr-engine/tools/det_verify.py` (AST ground truth), and every number is
reproduced by one offline command:

```
python3 experiments/ptr-engine/tools/matrix_audit.py            # writes measure/MATRIX-COVERAGE.json
python3 -m pytest experiments/ptr-engine/longrun/tests/test_matrix_audit.py -q
```

## 1. The declared cell space — 92 cells, derived independently of any matrix

A cell is `(rows_file, arm, checkpoint_id, rep)`. It is **declared** from the fixture and the row
files on disk, never from whatever `regrade-det.json` happens to contain:

| dimension | how it is derived | count |
|---|---|---|
| `rows_file` | every `rows-longrun-*.jsonl` in `experiments/ptr-engine/measure/` whose rows carry the fixture `task_id` = `LR-01` | 9 |
| `arm` | the arms that actually appear in that file's rows (e.g. `rows-longrun-v3` holds only 2) | 23 run/arm pairs |
| `checkpoint_id` | the fixture's own declarations: `fixture.checkpoints[0..2]` at turns 12, 24, 46 → `cp.0.t12`, `cp.1.t24`, `cp.2.t46`, plus `fixture.repair.at_turn` = 30 → `repair.t30` | 4 |
| `rep` | every rep value the rows declare | 1 |

**92 = 23 run/arm pairs × 4 declared checkpoint ids × 1 rep.**

Excluded, by rule and with nothing hidden: `rows-cell-*` (single-cell probe runs, 6 turns) and
`rows-pilot-*` (5-turn pilot) are not long-run grid batches and never reach checkpoint turn 12.
Including both would add 8 cells, **all `missing_turn_absent`** — it changes no pass, no fail and
no denominator. The 12 `acc.*` ids in the fixture are acceptance checks, not checkpoints; no rows
file carries an answer for any of them, and they are not checkpoint cells in this grid.

Where the number **92** comes from: 4 checkpoint slots × 23 `(run file, arm)` pairs. It is not a
count of answers — it is the size of the space that *should* have been filled.

`5 + 38 + 29 + 7 + 0 + 0 + 13 = 92`. Per-cell evidence — run file, arm, rep, turn, state, the
judge's own reason string, answer sha256 — is in
[`measure/MATRIX-COVERAGE.json`](../experiments/ptr-engine/measure/MATRIX-COVERAGE.json).

Two facts the old "36 missing" figure hid:

- **29 cells are `missing_turn_absent`** — the batch stopped before that turn (the `-fix` and
  `-policy` batches hold 12 and 28 turns of the declared 48).
- **7 cells are `missing_answer_empty`** — a row exists at the checkpoint turn but its
  `content` is empty (e.g. `rows-longrun-2026-10-26.jsonl`, `transcript-grow`, turns 12/24/46:
  128 completion tokens, `content_sha256 = e3b0c442…` = the empty string). An empty answer is
  *not* a wrong answer, and it is certainly not a failed checkpoint.

The 13 `undecidable` cells are all `repair.t30`: the fixture declares the correct action as a
dialogue commitment, not a source fact, so `verify_probe` returns `undecidable` even where an
answer is present. They stay distinct from every `missing_*` and are excluded from the
denominator.

## 4. What this changes, and what it does not

- **Known-wrong published figures:** "all four arms 0/3" (config C) and "1/3" (V6) are wrong
  as *judge* statements — both were `grade_v3`/`grade_v4` readings of cells that the AST judge
  decides differently (1 pass and 2 passes respectively). "5/92" is wrong as a *denominator*:
  the correct statement of the same record is 5/43 over 43 decidable cells, with 36 missing.
- **Not wrong:** the config-C *missingness* claim. All 12 config-C checkpoint cells exist;
  that grid's defect was the instrument and the starved fixture pointers, not absent rows.
- **Still unwarranted:** any arm-quality ranking. 36/92 declared cells are answerless and each
  arm's decidable n is between 6 and 19; a single flipped cell moves a rate by 5–17 points.
- The 7 `missing_answer_empty` cells are newly visible. The earlier record folded them into
  "missing" (reason *"no row with assistant answer text at this turn"*), which is accurate
  prose but hides that a row was returned with empty content — a serving/truncation fact worth
  following up, not a wrong answer.

States, counts and `arm × state` table are regenerated by `matrix_audit.py`; the red→green
guard is `test_matrix_audit.py` (11 tests), and reverting the audit to fold `missing_*` into
`fail` makes 7 of them fail, including `overall 5/79 (pass 5, fail 74, missing 0, undecidable 13)`.
