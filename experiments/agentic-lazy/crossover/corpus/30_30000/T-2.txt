TOOL T-2 -- split_fields

If the lockfile diff is large and surprising, that is itself the finding, not churn to ignore. The mirror caches on first request and serves subsequent requests locally. Readers never observe a partially written segment. Segments are sized for read amplification, not for throughput, and shrinking them multiplies the number of sealed segments a reader must hold. Every build pulls images and packages through an internal mirror rather than from upstream. Do not use this for a test that has never passed; that is authoring, not triage. Memory is O(rows) and no chunking is performed. The tool does not create directories, so a mistyped export path fails loudly instead of scattering files. Descriptions that narrate the implementation ("refactored X, renamed Y") without stating the why get reviewed as if the why were obvious, and it rarely is. Pushing from a build host fails authorisation and is deliberate. Do not call it on a stream wider than available RAM.
