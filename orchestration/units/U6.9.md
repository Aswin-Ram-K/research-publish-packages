# U6.9 — one bind decision, honoured on every entry point

**Status:** done (with one honest negative: the card's `state/state.sqlite` v3 pin is stale).

## Purpose
A security-relevant inconsistency: `--host 0.0.0.0` was refused on one entry point and
**bypassed on another**, and the bypassing path bound the dashboard — whose **read** routes are
open — to **every interface**.

## Findings
* `src/resextract/__main__.py` **did not exist** (`python -m resextract` → exit 1, "No module named
  resextract.__main__"). The file the card describes is `src/resextract/dashboard/__main__.py`,
  which contained the bypass verbatim:
  `allow_remote = args.allow_remote or (explicit_host and not is_loopback(host))`.
* The console script is `resextract.cli:main` (pyproject), so `.venv/bin/resextract serve` and
  `python -m resextract.cli serve` are the *same* callable and both consult `check_bind_host`.

## Fix
* Single decision site: `resextract.dashboard.app.check_bind_host`. An explicit `--host` is not an
  opt-in; only `--allow-remote` / `allow_remote=True` authorises a non-loopback bind.
* Removed the inference from `dashboard/__main__.py`; `create_app` re-validates through the same
  guard; `cli._resolve_serve` calls it with the user's own flag.
* Added `src/resextract/__main__.py` delegating to `cli.main`, so `python -m resextract` reaches the
  same decision instead of not existing.

## Guards (red→green, sha-proven, full `__pycache__` purge)
* (a) restore the inference → 3 failed / 4 passed; restore bit-identical (`3d982b3a…`).
* (b) make the guard ignore `allow_remote` → 2 failed (`assert 2 == 0`); restore (`ed849279…`).

## Write-path deviation (disclosed)
`src/resextract/dashboard/__main__.py` is not in this unit's declared write paths; it is the file
the card names (`src/resextract/__main__.py`) under its real name, and it held the bypass. No
sibling unit owns it.
