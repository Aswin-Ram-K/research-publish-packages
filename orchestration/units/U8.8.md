## What was done

1. **Reproduced** (`state/logs/U8.8-repro.txt`): a copy of the real graph with 5 nodes dropped
   (valid JSON, `built_at_commit` untouched, bytes now `7fca157f055e` vs real `4790bbb1111b`)
   is returned by `_reuse_candidate` and reported **`fresh`** — the expected digest appears
   nowhere, `notes == []`. `graph.json` has **no** `sha256` field; the only digest is
   `run.py::_graph_digest` reported into `counts["sha256"]`. A digest *inside* the artifact is
   written by the same writer as the bytes, so it can never vouch for the artifact.
2. **Pinned outside the artifact**: `config/graph_pin.toml` (committed, durable, reviewable in a
   git diff, read with `tomllib`, absent/malformed ⇒ *no pin*, never a failure).
3. **New state**: `digest_state = match | mismatch | unpinned` on `counts["provenance"]` plus
   `pin_sha256` / `digest_detail`; the shared `_provenance_stamp` line carries the digest clause.
   Default policy for `mismatch`: **unusable** — not reused, reported loudly, file kept on disk
   byte-for-byte; `allow_graph_digest_mismatch=True` is the operator override. `unpinned` is
   `unverified` and still reused. Staleness stays **report-only** (`require_fresh_graph` opt-in).
4. **Tests** (40 → 45, 0 deletions): mismatch refused + loud + kept + plan/run agree; match reuses
   with no false alarm; absent pin ⇒ `unpinned`, reused, `status=ok`; staleness still report-only
   with a matching pin (and `require_fresh_graph` still refuses); digest decision inside the single
   shared function (spy = exactly 2 calls, both `None`).
5. **Red→green**: `run.py` sha256 `78c989a0a3307375…` before and after both cycles, `cmp` CLEAN.
   (a) `pin = None` ⇒ the mismatch guard FAILS (tampered bytes reused as fine). (b) absent pin ⇒
   bogus digest ⇒ the no-pin guard FAILS (a missing pin hard-fails a run). Full `__pycache__`
   purge + `PYTHONDONTWRITEBYTECODE=1` between every revert and restore.
6. **Live** (`state/logs/U8.8-live.txt`): dry run exit **0**, graph line carries
   `… — STALE; sha256 4790bbb1111b matches the pinned digest 4790bbb1111b…`, `state/run` +
   `state/kg` tree hashes identical before/after (writes nothing). Mismatch demo in a scratch cwd
   with a scratch **copy** of the committed pin ⇒ `_reuse_candidate -> None`, loud

## Residual after the fix

The pin detects **change, not goodness**: a graph and its pin replaced consistently by a local
writer; a valid-JSON truncation re-pinned to its own digest; unpinned paths (still reused,
unverified); the graph's own build revision (target HEAD is recorded, not the builder's); no pin
history, so a rollback to an old pinned digest is indistinguishable. Semantic completeness
(2685 nodes / 7102 edges) is beyond any digest.
