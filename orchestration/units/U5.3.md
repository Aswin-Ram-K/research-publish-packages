## Purpose

One command that takes a lane, copies the material its claims actually rest on
out of the **read-only** target repo, assembles the docket **from those copies**,
verifies it, and records the `dockets` row. First CLI command that produces a
finished artifact. No LLM calls (Occamy probe `000`, as expected).

## What was built

* **`materialize.py`** — `LaneSpec`/`MemberSpec` (`from_store`, `from_json`),
  `MaterializedDocket`, `MaterializeRefused`/`MaterializeError`,
  `refs_to_copy_requests(...)` → `RefPlan`, `materialize_lane(...)`.
  * Ref shapes: `path#L120-L160`, `path#L120`, `path:L120` (U2.1's graph-node-id
    shape), bare graph node id (resolved through the graph to `source_file` +
    `source_location`; external nodes with no source file are reported, not
    guessed), bare relative path. Dedup by destination; unresolvable refs are
    returned in `RefPlan.unresolved`/**`MaterializedDocket.unresolved_refs`**.
  * Destinations: `material/{code,docs,figures,data}/<basename>` by extension,
    collisions disambiguated with a 6-hex path hash.
  * Containment by realpath **before** any read; `../`, `/etc/passwd` and
    symlinks never become requests.
  * Guard: zero verifiable refs ⇒ `MaterializeRefused`, nothing written.
  * Target HEAD re-read via `git rev-parse HEAD` at the moment of copying and
    recorded in the manifest **and** the `dockets` row.
  * `material_report_from_docket` reads the docket's **own** copies; the real
    source path is written back onto each item so `MANIFEST.json` records where
    the bytes came from.
  * `verify_docket` must be ok or `MaterializeError` is raised — an unverified
    docket is never registered.
  * Idempotent: `Copier` reports `unchanged`, `assemble` preserves `ITEM.md.r1`
    and appends `HISTORY.md`, the row is updated by `dir` (never duplicated).
* **`cli.py`** — real `materialize --target SLUG [--lane|--lane-file]
  [--docket-root DIR] [--dry-run] [--json]`; exits 0 / 3 (lane not found or
  refusal) / 2 (target missing, store unreadable). `PLACEHOLDERS` 11 → 10;
  new `cli.IMPLEMENTED = {doctor, status, materialize}`.
* **`tests/test_cli.py`** — restructured, nothing deleted: `materialize` leaves
  `EXPECTED_PLACEHOLDERS`; the file now pins (a) every remaining placeholder
  names a batch and no bare unit id, (b) registered subcommands ==
  `IMPLEMENTED ∪ PLACEHOLDERS`, (c) `materialize` carries its real flags.
