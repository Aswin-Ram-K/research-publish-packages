# U0.16 — remove the false-green `live` skip rule

**Purpose (one):** stop `tests/conftest.py` deciding skips from a name/keyword,
and make `live` an explicit `@pytest.mark.live` marker.

## Declared write paths
`tests/conftest.py`, `pyproject.toml` (marker registration only),
`tests/test_live_marker_convention.py`, `state/logs/U0.16*`,
`orchestration/units/U0.16.md`, `orchestration/handoffs/U0.16.json`.

## Hard bound
≤25 tool calls; `--collect-only -q` for counts; no full-suite run; zero LLM
calls; no live network; no commit; `PYTHONDONTWRITEBYTECODE=1` + `__pycache__`
purge around the revert/restore comparison.

## The defect, verbatim (old `tests/conftest.py` lines 39–45)

```python
def pytest_collection_modifyitems(config: pytest.Config, items: list[pytest.Item]) -> None:
    if config.getoption("--live") or os.environ.get("RESEXTRACT_LIVE") == "1":
        return
    skip = pytest.mark.skip(reason="live test — run with --live or RESEXTRACT_LIVE=1")
    for item in items:
        if "live" in item.keywords:
            item.add_marker(skip)
```

## What it actually matched on (measured, pytest 9.1.1)

`"live" in item.keywords` is a membership test on **exact bare keyword keys**,
not a substring of the item name. pytest builds those keys from the item's own
full name, the module/class names, mark names, and — the trap — **each
parametrisation id as a bare key**:

| probe item | keywords keys containing "live" | matched? |
|---|---|---|
| `test_lively` | `test_lively` | no |
| `test_livewire` | `test_livewire` | no |
| `test_olive` | `test_olive` | no |
| `test_param[live]` | `live` | **YES → silently skipped** |
| `test_marked` (`@pytest.mark.live`) | `live` | yes (correct) |

So the sibling's gotcha is real but narrower than "name contains `live`": the
live channel is a bare parametrisation id, a module/class named `live`, or the
mark. Any of them silently skipped a test that never used the network.

## Fix

* Skip decision is now `item.get_closest_marker("live")` — marker only, no
  name fallback anywhere.
* `--live` / `RESEXTRACT_LIVE=1` unchanged (`_live_enabled`).
* Marker registered in `pyproject.toml` `[tool.pytest.ini_options].markers`.
* `pytest_terminal_summary` prints a red
  `N live test(s) SKIPPED — NOT run and NOT passed` line when live-marked items
  were skipped, so "N skipped" cannot be misread as "N passed". The hook only
  *adds* a summary line; it cannot make a failing test look skipped.
