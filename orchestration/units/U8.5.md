acceptance entry point (PLAN §1.2): (1) the dry run planned `graphify` for the
`graph` stage while the real run reused an existing graph; (2) run-scoped

## What changed
- `run.py`: new `_reuse_candidate()` is called by **both** the dry run and the
  real run, so the plan cannot describe a `graphify` build the run will not do.
  The graph stage now reports `mode=reuse`, node/edge counts and the graph
  sha256 prefix in both; the dry-run reason reads *"dry run: would reuse …"*.
- `run.py`: `_copy_store()` switches the fresh copy to a rollback journal
  (`PRAGMA journal_mode=DELETE`); `_finalize_store()` checkpoints/cleans only
  when the copy is **not** WAL, so nothing a live database needs is removed.
- `run.py`: `EXIT_STATUS` + `status_for()`; `RunReport.ok`/`.status` are
  **properties derived from `exit_code`** (not stored fields), and appear in
  `as_dict()` — they cannot disagree with the exit code.
