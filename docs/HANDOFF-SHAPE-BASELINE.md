## Why this unit stopped at BLOCKED

`frozen_baselines()` in `tests/test_orchestration_handoffs.py` reads exactly two hash-pinned paths:

* `state/logs/U8.15/baseline_gaps.json` (pin `BASELINE_GAPS_SHA256`)
* `state/logs/U8.18/verifier_shape_baseline.json` (pin `VERIFIER_BASELINE_SHA256`)

and caches them in the module global `_BASELINES`. There is no glob, no directory scan, no third
path and no environment hook, so **no file written under `state/logs/` can reach that loader**. The
only two routes to green are:

1. add the 13 entries to the pinned U8.18 baseline **and** update `VERIFIER_BASELINE_SHA256` in the
   test — two edits inside the frozen guard; or
2. the one line that makes the dated record live, also inside the guard:

```python
_ext = json.loads((ROOT / "state" / "logs" / "handoff-shape-baseline-2026-10-26.json").read_text())
_BASELINES["verifier_gaps"].update({k: list(v["missing_keys_as_the_guard_measures"]) for k, v in _ext["entries"].items()})
```

Both are edits to `tests/test_orchestration_handoffs.py`, which this unit may not make — and buying
green that way is the failure this batch exists to end. (A third route exists and is rejected: a
`tests/conftest.py` hook that pre-populates `_BASELINES` would exempt the same files while leaving
the guard's own text untouched. That is the same act made harder to see.)

The dated record is therefore written and **not applied** (`"applied": false`), with the exact
loader line recorded in it, so the unit that is allowed to change the guard needs no re-derivation.

## What has to happen next, and the honest limit

Either fix the classifier (a `V*` handoff that carries the 7 unit keys and no verdict keys is a unit
handoff, whatever its name — `classify()` currently keys on the prefix first and never looks at the
unit shape), or apply the dated record with the loader line and accept that the guard keeps
producing this false positive. Freezing alone does not hold: **any future unit whose handoff name
begins with `V`, or that reports an `overall` scalar, becomes the 14th** — the red direction above
is that prediction, executed. When the classifier is fixed, `test_no_baseline_entry_over_declares`
will fire on any applied entry (`checks` exempted on a file that now measures no gap), which is the
guard's own mechanism for forcing the exemption's removal.
