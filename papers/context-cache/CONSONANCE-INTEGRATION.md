## A. The convergence that matters most

Consonance registered (CLOSE) one measurement and its mechanism. `MEASURED_FACTS.md` **F1** (`docs/research/experiments/EXP#43-context-cost-under-cache.md`): a re-rendered compact projection cut **payload 24.2 %** and **billed 2.4 %**, and was **more expensive than the full transcript from step 3 on**. **F2**, same experiment: its main call was served with **0 cached tokens at every step** (0/134, 0/426, 0/499, 0/569, 0/663) while the transcript's cached share **climbed 0 → 0.166 → 0.217 → 0.350 → 0.489**. F2 + F3 is their load-bearing pair: *payload size is not the lever; prefix stability is* (F3: 48 of 72 prefix bytes moved on a depth change).

This project measured the same mechanism today, independently — `orchestration/handoffs/C0-EQUALINFO.json` (`uncached_per_turn_by_arm`; rows `experiments/ptr-engine/measure/rows-equalinfo-2026-10-26.jsonl`), occamy-1.0-NVFP4 on SGLang `:8012`, all 12 bodies in every prompt, nothing truncated (`truncation.dropped` empty):

| arm | uncached tokens / turn | TTFT | what the prefix did |
|---|---:|---:|---|
| plain transcript `C0F` | **1,911.2** (rep1 5,676.5 = cold prime; rep2/3 **28.5**) | 0.182 s | byte-identical every turn → `cached_tokens 22528` |
| transcript + index line `C0FT` | 46.7 | 0.181 s | identical still |
| pointer protocol `R` | **3,524.0** (9,476 / 1,044 / 52 by rep) | 0.602 s | a fetch appends per resolve → prefix moves |

**1.8441x dearer per turn** (3,524.0/1,911.2), 1.6695x on the cold rep, with **accuracy 3/3 in all three arms** — the pointer arm loses on cost and buys nothing back on this task.

**An independent replication across workspaces, renderers and engines — with the dimensions named, because only some are provable.** Workspaces differ (`30b03b80` vs `78cead56`). Renderers differ: their compiler's *compact projection* (`MEASURED_FACTS.md`, "What our compiler does today") versus a 12-line index over a content-addressed store (`RECORD.md` §1: 447 B index, 22,528-token prefix here). Engines differ in fact but not yet in evidence: ours is SGLang `occamy-1.0-NVFP4` on `:8012`, B=64 measured; theirs cannot be ours (`handoff.json:division_of_labour.consonance_runs_no_hosting` = `true`) yet the F1 row carries no engine fingerprint, so neither file proves it — that is gap **B2**. What replicates is the *mechanism and its direction*, twice, on two harnesses: a payload cut that moves the prefix is paid back as lost reuse, and the arm that never changes its prefix wins the bill.

**What it means for the question actually being asked.** Both records are negatives of one shape, and the operator's aim, recorded 2026-10-26, is **not to prove the pointer system is cheaper but to bring it close enough**. That aim is not yet in `RECORD.md`, `CLAIMS.md` or `GAPS-INVENTORY.md` (a repo-wide search finds the phrasing only in corpus data), so this document fixes it: **the gap — 1.84x where nothing needs paging — is the target quantity**, and every experiment below is scored on how much of it it closes, not on who wins. `RECORD.md`'s own narrowing states the boundary the aim works inside: the pointer case survives only where the working set exceeds the window, or where history is cache-hostile.

## B. Contract gap list — what this project must change to be joinable

**B1 — `cached_tokens` semantics conflict; the fix is per-engine.** `INTERFACE_CONTRACT.md` §2: absent means *not reported (unknown), never 0*. `LIVE-CELLS-2.json:evidence.cell_A.usage_note` measured the opposite on SGLang — it "returns prompt_tokens_details but OMITS cached_tokens when it is 0; null therefore means 0" — and the same cell proves it: `P1 397` → `cached 320` → uncached 77, 3/3 reps, `cached_reported: true` (`:evidence.cell_A.append_prompt_tokens` `[397,397,397]`, `:evidence.cell_A.append_cached` `[320,320,320]`), the row file writing the reason inline as `cached_source: "absent(server omits cached_tokens when 0)"`. On vLLM the field is genuinely unknown: re-counted here, **0 of 52** rows report a cached token and `prompt_tokens_details` is JSON `null` on **52 of 52** (handoff and card say 45/45). **The rule that makes both true: sglang + absent → 0 (measured); vllm + null → unknown (never 0).** Without it a join silently converts unknown into zero — and `RECORD.md`'s 2026-10-26 layer ("a missing `cached_tokens` means 0, not 'not reported'") is that error committed as a *universal* sentence: true for `:8012`, false for `:8014`, so it needs engine scope at its source. Two package counts also fail to reproduce (SGLang 47/48 in `C0-EQUALINFO.json:vllm_cache_limit` vs **46/48**; vLLM 45/45 vs **0/52**): direction unchanged, but a join keyed to a handoff number rather than a row count will drift.

**B2 — the four fingerprints are absent from this project's row files.** `INTERFACE_CONTRACT.md` §1 makes arms comparable only if all four are equal. To add, per row *and* in `run.json`: `model_fingerprint` (id + revision / quantisation digest), `tokenizer_fingerprint` (tokenizer files or hash + chat-template hash), `renderer_fingerprint` (content digest of the module→bytes renderer), `engine_fingerprint` (image digest + the exact serving flags). What exists is weaker: `model` and `token_source` fields, `LIVE-CELLS-2.json:host_used`, and one config captured on `:8012` (`max_mamba_cache_size 64`, `cells/U2/server_config.json`, quoted `ADOPTION.md:17`) — a capture, not a digest, and no image id anywhere.

**B3 — the 2026-10-26 runs are retrospective by the contract's own rule.** §3 freezes `run.json` *before* the first call and says a later envelope "is not a pre-registered run; mark it `retrospective:true`". Neither `rows-equalinfo-2026-10-26.jsonl` nor `rows-live-2026-10-26.jsonl` has a `run.json` at all, so both are **retrospective** and must be reported as such, however clean the rows. (`quality/PREREG.json:registered_before_any_request` is the counter-example: one arm did freeze first.)

**B4 — `uncached_prefill_tokens` is derived here, never measured.** Both files compute it as `prompt_tokens − cached_tokens` (`C0-EQUALINFO.json:uncached_per_turn_by_arm.basis`); under §2 it belongs under `derived` with the formula named in the key (`uncached_prefill_tokens_from_prompt_minus_cached`) and may never be quoted as a measurement. A third quantity must not be confused with either: the law's `predicted_uncached` (`ledger.py:420-448`) is a model, not an observation.

## C. The six experiments mapped onto this project's evidence

**E1 CACHE-BOUNDARY-SWEEP — PARTLY.** The instrument E1 wants is already fitted: residue law `cached = 64·floor((P1−1)/64)`, `uncached = (P1 mod 64) + L`, `L = n_payload + 12` (`RECORD.md` §2; `LAW.md:83-93`, 186/186 rows residual 0). Its residue-0 anchor was measured today — primer 384 → append **397** → `cached 320` (3/3, `cached_reported: true`) → uncached 77, 5.16x, which decided the C1 branch `RECORD.md` left open — and warm cells exist at residues 2 and 5 (`cached 384` at P1 386, `cached 320` at P1 325; cells B and A of `experiments/ptr-engine/measure/rows.jsonl`, uncached 15 and 18), while the vLLM append re-bills cold (`cached 0`, ttft 1.770/1.773 s, `LIVE-CELLS-2.json:evidence.cell_C.append_cached`). **Still missing is the sweep**: ≥8 rewrite offsets walked **tail→head**, 3 reps, one frozen build. The never-sent control (prime rows, `cached=0`) and identical-repeat control (cell A resend) exist; a **mismatched-tokenizer arm does not exist at all**. Cells E1 still needs: SGLang B=64 offsets placed so that "monotone in offset" and "block alignment only" predict *differently* — that comparison is the falsifier. Budget compatible: 8 offsets × 3 = 24, four controls × 3 = 12, 3 tokenizer-mismatch = **39/60**.

**E2 CHECKPOINT-COST — PARTLY, and this is the premise.** An adjacent arm exists: compaction bills ≈**1,407.7** uncached tokens/turn against the static transcript's **1,911.2** (card figure — no file on disk carries it), and the arm is the predecessor baseline, **0/3 on both models by construction** because `k01` was never in context (`C0-BASELINE.json:finding`, `:c0_accuracy` sglang 0/3, vllm 0/3). **The economics answer exists; the quality answer does not** — ≈26 % cheaper per turn with nothing showing the task still completes. E2 adds three arms on one fixture and one verifier — **A** append-only, **B** one checkpoint at ~70 % of budget, **C** checkpoints every ~20 steps — reporting **time-to-verified-success** and per-row `verified_success`, seed/temperature pinned. Controls: the append arm's climbing cached share is the existing `C0F` 5,676.5 → 28.5 → 28.5 shape; **a no-op checkpoint must cost ≈0** is new.

**E3 ORDERING — NEW, cheap, and the best lever on "close enough".** ≤40 calls; placing volatile material in the suffix keeps the frozen prefix byte-identical — exactly the asset the transcript holds (`cached_tokens 22528`, a prefix that never moves) and the pointer arm spends on every resolve. The mechanism is adjacent but unmeasured here: `CLAIMS.md` **C67/C67a** found a mid-run edit in a cached prefix null on three setups and **costing** on the fourth (O4 P3−P1 **+23.5211 [8.39, 53.48]**), so the "volatile early" side is pre-observed on one setup only. **E4 32K DENSE TIER — NEW, and the only experiment that needs vLLM.** `qwen3.5-9b` has `max_model_len 32768` (`MEASURED_FACTS.md` windows table; `LIVE-CELLS-2.json:hosts_probed` 200) and reports **no cache counters** (0/52 here), so it can carry **verified success, gross tokens and time-to-verified-success but no hit rate** — a capability claim only, per `DO_NOT_REDO.md` #3. ## D. The vLLM retirement decision

**The instrument, measured.** SGLang reports `cached_tokens` on **46 of 48** rows in the 2026-10-26 file and on **880/880** and **888/888** hot rows in the grid cells (`CLAIMS.md` **C55**, **C57**). The `:8014` vLLM build reports it on **0 of 52** (`prompt_tokens_details` JSON `null`, 52/52; handoff says 0/45). On the axis every cache claim depends on, one engine is an instrument and the other is a mute.

**Decision.** Retire vLLM from **every cache, cost and hit-rate claim**, keeping exactly one use: **E4's 32K dense tier, capability only** — verified success, gross tokens, time-to-verified-success, never a hit rate. That follows from the counts and from `DO_NOT_REDO.md` #3; it is not a preference.

**What it costs the paper.** Cross-engine replication cannot be extended or re-derived. **C55**'s vLLM legs (V1 1088 on 300/300, V2 1056 on 268/268, V3 2096 on 16/16), **C63**'s 2×2 and its engine main effect (+549.33 [462.4, 631.9]) — which needs both engines by construction — and **C51**/**C60**/**C50** rest on vLLM cells that *did* report counters, on stack `vllm-0.27.1` (`C63` source `R2P-O4`). Those stand as history and are not retracted; what is lost is the ability to add, repeat or re-derive a vLLM leg on the live rig. So every table mixing those columns with live rows **must** say "engine-specific, stack `vllm-0.27.1`" — #4 forbids comparing arms across builds, making the label a requirement rather than a note — and no *new* cache claim gets second-engine confirmation: C55/C63 become "live single-engine + frozen cross-engine history".

**Why it cannot be repaired cheaply.** vLLM's counters are launch flags, so a repair *is* a relaunch. #5 keeps `gx10-occamy-nvfp4` up and treats a variant container as leaving production not running (restore verified by `:8012/v1/models` returning `occamy-1.0`, never `/health`). Both engines bind the same box (`LIVE-CELLS-2.json:host_used`, `192.168.2.168:8012` + `:8014`) and #9 warns a concurrent job there moves TTFT enough to invert an arm — so the repair is a production-container decision on a shared host, not a flag we can turn.
