# U8.76 — guard the SQLite sidecar rules (`*.sqlite-wal` / `-shm` / `-journal`)

Unit card (U8.76). Scope: `tests/test_repo_hygiene.py` only. No `src/**`, no `docs/**`.

## Purpose
`U8.74` handed up the "same global-rule treatment" for the SQLite sidecar rules it
identified at `.gitignore:20-22`. This unit decides whether anything is actually
broken, fixes only that, and pins the rules with behavioural + structural guard
tests in the same style as `U8.74`'s `**/*.tmp` work.

## Probe
`curl -sS -m 5 -o /dev/null -w '%{http_code}\n' http://192.168.2.168:8012/v1/models` → `000`
(exit 7, connection refused). No restart attempted, **zero live LLM calls**.

## What the real state is
`.gitignore:20-22`, verbatim, already **global by design** (no leading `/`, no
directory component), with the comment at 18-19 stating the intent:

```
18: # SQLite sidecars are runtime state, never source.  Global by design: any
19: # *.sqlite database can grow a -wal/-shm/-journal next to it.
20: *.sqlite-wal
21: *.sqlite-shm
22: *.sqlite-journal
```

`git check-ignore -v --no-index` on the real rules, verbatim:

```
.gitignore:20:*.sqlite-wal	state.sqlite-wal
.gitignore:21:*.sqlite-shm	orchestration/units/state.sqlite-shm
.gitignore:22:*.sqlite-journal	src/resextract/state.sqlite-journal
.gitignore:21:*.sqlite-shm	state.sqlite-shm
.gitignore:22:*.sqlite-journal	state.sqlite-journal
```

i.e. a sidecar is ignored at ROOT **and** at DEPTH, and the match is attributed to
lines 20-22 — not to a parent-directory rule (`/state/` is root-anchored, line 7,
and the probe parents `src`, `src/resextract`, `orchestration`, `orchestration/units`
are all `rc=1` / not ignored).

## Verdict: nothing was broken → no `.gitignore` change
Neither of the two failure modes that would have required an edit exists:
there is **no** root-anchored-only form to replace, and the rules already cover a
sidecar beside a database at the repo root *and* several directories deep.
So the file is left untouched — `git diff --exit-code -- .gitignore` is clean and
`sha256(.gitignore)` == `git show HEAD:.gitignore | sha256sum`
(`27f4f10aa11a8217afd90455fb6faafa17ca204d00d44dfb14a2ab86b2ca60da`).
What was missing was *coverage*, so the guard is what this unit adds.

## What was added — `tests/test_repo_hygiene.py`, section 6
1. `test_sidecar_paths_are_ignored_at_any_depth[state.sqlite-wal | orchestration/units/state.sqlite-shm | src/resextract/state.sqlite-journal]`
   — behavioural: `git check-ignore --quiet --no-index` exit code, **plus** an
   inside-test proof that the probe parent is not itself ignored (so the assertion
   cannot be satisfied transitively) **plus** `not (REPO_ROOT / path).exists()`.
2. `test_gitignore_declares_a_global_sidecar_rule[-wal | -shm | -journal]`
   — structural: parses the real `.gitignore` (or the copy the env seam points at)
   and requires a rule that is **global** (`_pattern_is_global`), so a
   root-anchored `/state.sqlite-wal` is matched by the parse and then rejected.

Seam: reuses `U8.74`'s `U874_GITIGNORE` env var. `U8.74` used it only for the
parse; `U8.76` additionally points the `check-ignore` probes at a throwaway work
tree (`state/verify/U8.76/redrepo/`, `git init` + the copy as `.gitignore`) whose
only ignore file is the copy, because `git check-ignore` has no "use that file"
flag and `core.excludesFile` is *lower* precedence than the repo's own
`.gitignore`. No file on disk is edited; the stub is rebuilt when the copy's bytes
change and removed after the red runs.

## Scope limit (deliberate)
`state/state.sqlite` itself is **not** covered or named by anything added here —
it is only referenced by the pre-existing `test_root_state_is_ignored`. The
open question (version the root DB or not) is the user's, exactly like `/dockets/`.
