# U5.8 — material provenance must survive a bare re-assembly

**Purpose.** Fix the silent downgrade V5B found: a bare re-assembly of a docket converted
commit-verified material (`git_object` + `blob_sha`) into `working_tree`, without erroring and
without `verify_docket` noticing.

**Fix (src/resextract/docket/assemble.py).** New `_inherit_material_provenance(material, previous)`
called once, right after the existing manifest is read (`downgrades.extend(...)`). For every row it
inherits `resolved_from`/`blob_sha`/`unpinned` from the existing manifest **iff** `dest` and `sha256`
both match; changed bytes are recomputed (never inherited — a pin on different bytes is fabricated
provenance); new rows inherit nothing; every would-be downgrade is appended to the assembly report
and `HISTORY.md`. Same discipline U5.7 used for `generated_by.producer`. `materialize.py` was NOT
touched: that path re-derives provenance from live git resolutions and stamps it post-hoc
(`_record_manifest_evidence`), so it never lost it.

**Reproduced on a copy** (`state/U5.8-repro/`): 6/6 `git_object` → 0/6, manifest sha
`879e66b8…` → `433eb11a…` (timestamp-dependent), `verify_docket` **ok**, `downgrades` empty.

**Post-fix live** (`state/U5.8-live/`): 6/6 preserved, provenance block byte-identical, material
sha256 9/9 unchanged, 6 warnings recorded, blob_sha 6/6 vs `git rev-parse 5cdc471a…:<src>`.
