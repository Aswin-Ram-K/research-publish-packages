# U15 — live four-arm cell: is compaction cost head mutability?

**Status:** done — 160/160 rows, live run 2026-10-21T03:54:39Z → 03:55:40Z,
rows sha256 `7d93f795…17d8f8`. Verdict:
[`orchestration/handoffs/U15.json`](../handoffs/U15.json).

## Purpose (one)

Build **one** cell and run **four arms** over the same corpus slice, trigger,
compaction points and renderer, so the only thing that differs is whether the
chain's head is rewritten:

| arm | policy | head after compaction |
| --- | --- | --- |
| R | `summarise_in_place` | rewritten (summary replaces folded head) |
| F | `fork` | rewritten (new chain, `[fork]` provenance marker) |
| A | `append_note` | **unchanged** (one `[note] ...` summary node appended at the tail) |
| C | none | control — measures the ambient per-turn uncached residual |

The question: **does Arm A beat Arm R by ≥1.5× on total uncached tokens?**
If yes, the salvageable claim is "cost is head mutability, not edit-vs-fork";
if no, the refutation of an edit-vs-fork advantage stands unqualified.

## Fixed design

- Corpus: `experiments/context-cache/corpora/endtoend.json`, scenario `E1`,
  turns 1–40 (gold turn 17 included).
- Trigger: `needs_compaction` at **8192** estimated tokens
  (`default_est_tokens`, ~4 chars/token).
- Compaction points: **turns 18 and 35 in every arm** — derived once offline by
  simulating the reference arm (R), so the trigger is not arm-dependent.
- `keep_last=2`; renderer `RenderPolicy.NAIVE_APPEND` everywhere.
- Summariser: deterministic offline stub, whitespace-collapsed folded text
  truncated to 750 chars (~188 est tokens, matching the corpus's
  `summary_hint_est_tokens`), identical for every arm. No extra model call:
  the unit measures cache, not summary quality, and a live summariser would
  make the compaction points non-deterministic.
- Fresh per-arm salt (`make_salt` seeds 1501–1504) → cold isolation, **never**
  `POST /flush_cache`.
- `max_tokens=4`, `thinking=False`, `stream=True`, one request in flight,
  strictly serial.

## Bound

- **160 live requests** (4 arms × 40 turns), hard cap **220**; the driver
  aborts at an internal guard of 210.
- Endpoint lock: `flock` on `experiments/context-cache/.occamy.lock`, 5-minute
  timeout; on timeout the unit writes a blocker and stops (no hang).
- Max attempts per request: `client.chat`'s own 2 attempts; no manual retry
  loop.
- Bound on scope: this unit only reports; it does not change `src/` or `tests/`.

## Measurement rules encoded

- Actual `prompt_tokens` / `cached_tokens` recorded on **every** request; the
  64-token grid is never assumed in analysis.
- Exact multiples of 64 on a normal appended turn are warmed twice (U10), and
  both sends are logged; at a scheduled break turn `cached == 0` is the thing
  being measured and is *not* retried.
- Turn 1 of each arm must report `cached == 0`; a violation aborts the run
  (salt collision would invalidate the cell).

## Durability

Each row is appended to `rows.jsonl` and `fsync`-ed immediately. On startup
the driver skips every `(arm, turn)` already present and replays the chain
deterministically, so a crash loses at most one in-flight request and a rerun
resumes for free.

## Report shape

Unit handoff (`unit, status, artifacts, evidence, blocker, next_unit_hint,
write_paths`) plus the plain answer and, per arm, total prompt tokens, total

## Result (measured 2026-10-21, 61 s, 160 requests, no warm retries, no anomalies)

| arm | total prompt | total uncached | hit rate | breaks | break cost net of C |
| --- | --- | --- | --- | --- | --- |
| R summarise_in_place | 194,788 | 51,172 | 0.7373 | 2 (t18, t35) | 1,620 |
| F fork | 198,376 | 47,080 | 0.7627 | 2 (t18, t35) | 1,975 |
| A append_note | 412,177 | 30,097 | 0.9270 | 0 | 0 |
| C control | 403,259 | 30,523 | 0.9243 | 0 | 0 |

- **A beats R by 1.700× on total uncached tokens → the ≥1.5× test passes;
  R and F are within 8.0 %, so edit-vs-fork is not the driver.**
- Decomposition: net break cost at the two compaction turns is only 1,620 of
  R's 20,649-token excess over C (7.8 %); the other 19,029 (92.2 %) is the
  post-compaction steady state (R: 1,660 uncached/turn on a 5,812-token
  window; C: 755/turn on 12,839). With only the break effect and C's ambient
  residual, R would be 32,143 and A/R would be 1.07×.
- Arm A never compacts, so its prompt grows 1,186 → 19,583 tokens
  (+18,397, 16.5×) and its total prompt mass is 412,177 (+8,918 over C, the
  two `[note]` nodes). That is the window cost of never compacting.
- Pre-compaction (turns 1–17) R = F = A = C within 30 tokens — the arms are
  the same workload before the first fold.
