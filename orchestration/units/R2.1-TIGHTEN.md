## Normative content of R2.1 (what changed)

1. **Matching unit:** per **occurrence**; a `tokenize` **NAME** token matched by its
   underscore-separated parts, case-insensitively (`record_refusal` carries `record`;
   `recording` does **not**); never line-level, never substring containment.
2. **Range scope:** the checkpoint's cited `path#Lstart-Lend` (single line = one-line
   range; no fragment = whole file). This moves `ledger`'s evidence :33→:66 and
   `scope`'s :43→:66; **classes unchanged 11/11**.
3. **Code vs prose:** NAME tokens count (including f-string replacement fields on
   ≥3.12); STRING (every continuation line of a multi-line docstring), COMMENT and all
   FSTRING_* tokens do not. Worked examples for `resolve.py:143` (`spent`,
   FSTRING_MIDDLE) and `resolve.py:47` (`budget`, continuation of the STRING opened at
   :44) — the two families that diverged under R2.
4. **Declared scope limit:** R2.1 judges *which tokens must appear*, not meaning. A
   negated sentence naming every anchor passes; that is a **known, accepted limitation**
   of a mention-based checkpoint metric, to be complemented by a semantic tier (separate
   card), never silently upgraded.
5. **Interpreter pin:** CPython ≥3.12 (measured 3.14.4); below 3.11 an f-string is one
   STRING token and its replacement fields stop being NAME tokens — the 11 cells were
   checked to be version-invariant, and the change is stated, not assumed.
6. **Attestation:** sha256 of the delimited rule body
   `b16548301589593b8d1041325fce833ef60d3b39b8e8c0a205084ee35eb9ad57`, written
   `2026-10-26T13:46:53Z`, reproducible via `anchor_classify.rule_digest()` and asserted
   by a test — the gap that made R2's 13:29:21Z freeze unverifiable.
