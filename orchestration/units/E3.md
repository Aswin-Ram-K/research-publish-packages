## Decomposition this unit measures (the core idea)

For one request with `L = prompt_tokens`, `m = cached_tokens`, and the previous full prompt in the
same chain `L_prev`:

- `residual   = (L - m) - (L % 64)`                      (U2's definition; 0 for identical repeats)
- `tail_term  = L - 64*floor(L_prev/64) - (L % 64)`      (residual if only the *previous* prompt is reused)
- `deficit    = tail_term - residual = 64*floor(L_prev/64) - m`   (tokens lost beyond the new tail)

`deficit == 0` on an append means the deviation is **fully** explained by the appended tail not being
in the cache yet (plain prefix identity). `deficit > 0` means state that should have been reusable was
not reused -- the only quantity a mamba-checkpoint story can explain. A **byte-identical repeat of the
appended prompt**: residual 0 means the state *was* retained after completion (loss is at the append
match, i.e. granularity); residual > 0 means the state was never retained / was evicted.
