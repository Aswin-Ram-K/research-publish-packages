## The A trade-off — which was chosen and why

Removing the commit id costs a verifier the ability to check provenance against the private repo
(`git cat-file`/`merge-base`/`rev-parse` on that id). Keeping it leaks private-history structure — an
unreachable, force-rewritten private commit, its date, and the private directory it was carved from — and it is
**unverifiable to every reader this release is published to**. The fresh-export rule is "no `.git`, no history",
and a SHA reference *is* history. **Chosen: remove the id**, with four substitutes, none of them a silent drop:
per-file content identity (`source_sha256` per harness entry + `INTEGRITY.md` §1); the preserved, attributed
byte-identity claim (the three blob digests `18966eff5…`/`68c39632…`/`15858fcd…`); the release-process rule in
`README.md` §6/`REDACTION_REPORT.md` §8; and the workspace audit trail, which keeps the id while the release does
not. The private path `tools/typed-channel/` is **kept, deliberately**: it survives **68×** inside the released
harness bytes themselves, so dropping it here would only be cosmetic while breaking the released files' byte
identity with their source. Recorded as irreducible in `RESIDUALS.md`.
