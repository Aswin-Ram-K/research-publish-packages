## Defect 1 — quiescence blind to writes in an EXISTING untracked path
`detect_concurrent_writer` now derives its watch set from `TargetPolicy.admit`
(never a second ignore implementation): git's `?? dir/` entry is enumerated
inside (bounded `scandir`, symlinked dirs not followed, `_is_ignored`
components such as `.worktrees/` never entered), then filtered by admission.
Each watched path gets a bounded identity on both sides of the window — content
sha256 for files ≤ 1 MiB, `(size, mtime_ns)` beyond that — and any change makes
the verdict `active_writer` with the path named. Caps: 2 000 paths, 32 MiB
hashed, 1 MiB per file; every binding cap lands in `signal.caps_hit`.
`assert_pinned_quiescent(target, pinned_paths, ...)` is the sealed window: the
caller pins the untracked paths its docket depends on; the signal carries
`head_before/head_after` for the mandatory post-hoc HEAD re-verification.
Limitations documented in the module docstring: an identical-rewrite within the
window is undetectable, and a burst can begin after the window closes.

## Defect 2 — a stale staged copy can be silently reused
`graph_state.json` (schema `resextract/refresh-graph/2`) now records
`staged_from_head` — the head the copy was actually copied at — plus `copy_head`
read from the copy's own `.git` (ground truth), alongside `observed_head`. The
reuse guard compares `staged_from_head` **and** `copy_head` to the current head
and the recorded graph sha; any mismatch, a legacy label, an unreadable copy
HEAD or an unobservable current head re-stages (fail toward correctness). A
re-stage is a real `rmtree` + copy, so files added between heads appear. Legacy
schema-1 state (only `observed_head`) is invalidated/recorded, never trusted.
A reuse pass writes nothing (state bytes + mtime unchanged).
